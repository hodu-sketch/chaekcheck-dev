## 숫자 읽는 법

- 질문 하나에 카드 최대 8장. Sonnet이 질문×책마다 0~3점을 매긴 **같은 채점표**로 모든 안을 셈.
- **맞음%** = 카드 중 2~3점(주제가 맞음). **아주 맞음%** = 3점(주제와 조건 — 대상·쉬움·나라·장르 — 이 다 맞음). **틀린 카드** = 질문 하나에 보이는 0~1점 카드 수.
- **흔들림**: 같은 입력을 두 번 돌리면 아주 맞음 ±1~3%p, 틀린 카드 ±0.2장 → **3%p 이하 차이는 차이로 보지 않음**.
- **드는 것**: 2차 AI에 넣는 글자 수(비용 대용), 서버 메모리·시간, 만드는 데 든 작업.

## 1. 단계별 (질문 50개) — [개선 보고서 1절](ai-search-improvement-2026-10-25.md)

| 단계 | 맞음 | 아주 맞음 | 틀린 카드 | 드는 것 |
|---|---|---|---|---|
| 1단계: LLM이 검색어로 바꿈 → 낱말 검색, 앞 8권 | 74% | 40% | 2.04 | LLM 1번 |
| 1+2단계: + 벡터 검색 섞기(RRF), 앞 8권 | 82% | 52% | 1.48 | + 질문 벡터 1번(서버 중간 106ms) |
| 1+3단계: + LLM 재평가 (그때 운영) | 92~94% | 62% | 0.48~0.68 | LLM 2번, 2차 입력 4,292자 |
| **1+2+3단계** (운영 코드로 만듦) | **96%** | **74%** | **0.34** | 2차 입력 4,243자(그대로) + 질문 벡터 1번 |

→ 1단계만일 때보다 **아주 맞음 40% → 74%, 틀린 카드 2.04 → 0.34장**.

## 5. 1차 AI 호출을 작은 모델로 — [1차 호출 보고서](ai-search-first-call-models-2026-10-25.md) · [넣은 것과 뺀 것](ai-search-ml-first-call-decisions-2026-10-26.md)

Sonnet이 만든 질문 3,000개(학습 2,306 / 시험 600)로, 1차 호출의 「고르기」 칸을 LLM 없이 맞힐 수 있는지.

| 칸 (시험 600개) | TF-IDF | KURE + 분류기 | Haiku |
|---|---|---|---|
| 책 찾기 아닌 말 / 제목만 / 앞 책 가리킴 (시험 600개 중 97%가 「아니오」라 거의 늘 맞음 — 유형만 모아 재면 5-5절) | 98.7 / 97.3 / 99.7% | 99.2 / 98.3 / 99.8% | 98.7 / 100 / 100% |
| 소설을 원하나 / 빼 달라는 말 | 97.2 / 93.7% | 97.7 / 93.2% | 99.5 / 97.3% |
| 큰 칸 F1 | 73.7% | **84.9%** | 93.4% |
| 작은 칸 F1 | 38.2% | 48.6% | **87.6%** |
| 드는 것 | 수 MB, 1ms | 1MB + 이미 있는 KURE, 1ms | API, 1~2.4초 |

| 다듬은 뒤 (칸마다 문턱 + 작은 신경망) 큰 칸 / 작은 칸 / 장르 / 분위기 | | 89.6 / 79.2 / 65.8 / 83.7% | 93.4 / 87.6 / 82.8 / 92.0% |

| 약한 칸 질문 3,000개 더 + 작은 신경망 (학습 5,300개) | | **90.7 / 85.0 / 71.6 / 88.4%** | 93.4 / 87.6 / 82.8 / 92.0% |

학습량에 따른 작은 칸 점수 (로지스틱 회귀 / 작은 신경망 MLP): 2,306개 79.2 / 78.5% → 3,306개 80.4 / 82.6% → 4,306개 80.6 / 84.2% → 5,300개 80.9 / 83.9% → 6,298개 81.6 / **86.5%** (Haiku 87.6%). MLP는 4,000~5,000개에서 거의 다 배움. 전체 표: [1차 호출 보고서 5-3절](ai-search-first-call-models-2026-10-25.md).

→ 예/아니오 칸은 분류기로 대신할 수 있고, 큰 칸·작은 칸·분위기는 Haiku와 3%p 안팎. 장르만 11%p 차이가 남음.

**전체 흐름에 넣으면** (질문 57개, 2차 Haiku까지): 1차를 LLM 없이 MLP 칸 + 질문 낱말(+ 책 주제어)로 바꾼 M·MT가 두 번 돌린 평균 아주 맞음 **72 / 71.5%**, 틀린 카드 **0.36 / 0.35**로 지금 운영 P(72%, 0.37)와 같음 — **책 찾는 질문에서는** 1차 Haiku 호출(1~2.4초, 비용 약 15%)을 없애도 최종 카드가 나빠지지 않음. 다만 **길 나누기(책 찾기 아님·제목만·앞 책 가리킴, 400개)는 Haiku 97.8% / MLP 58.5% / LR 37.0%** — 처음엔 분류기가 대신하지 못했으나(학습 질문에 이 유형이 1% 미만), **유형마다 400개씩 고르게 쓴 길 나누기 학습 질문 1,600개로 다시 학습하니 MLP 94.5% / LR 93.5%** (보통 질문을 막은 것 2 / 1개, Haiku 6개) — 첫 질문은 분류기, 이어 묻는 질문은 Haiku로 나눌 수 있음([5-6절](ai-search-first-call-models-2026-10-25.md)). 앞서 쓴 「98~100%」는 늘 「아니오」만 해도 97%가 나오는 칸이라 잘못된 인상이었음([5-5절](ai-search-first-call-models-2026-10-25.md)). [1차 호출 보고서 5-4절](ai-search-first-call-models-2026-10-25.md) Cross-Encoder(bge-reranker-v2-m3)는 비교용: 2스레드 PC에서 칸 22개 3.4초 · 172개 18.1초, 학습 없이 큰 칸 F1 37.5%(TF-IDF 73.7%, KURE 신경망 89.6%) — [4-1절](ai-search-first-call-models-2026-10-25.md).

**운영 뒤 고친 것** (v1.16.0에서 1차를 ML로 바꾼 뒤, [결정 기록 3-4](ai-search-ml-first-call-decisions-2026-10-26.md)): 짧은 장르 질문(「판타지」) 300개를 더해 길 나누기 74 → **97.3%**. 이어 묻는 질문은 「새 주제 규칙」이 171개 중 47번 잘못 켜져 「판타지인데 → 좀 슬프고 서정적인거」가 끊겼음 → 앞·지금 질문 벡터로 관계 7가지를 나누는 MLP(시험 700쌍 96.4%)로 바꾸고, 실제 대화 80개를 2차 Haiku까지 돌려 Sonnet 채점: 3번씩 돌린 평균 맞음 74.3 → **76.2%**(이 차이는 흔들림 안), 조건 더하기(continue) 67 → **76%**·카드 없는 답 13 → 8개(3번 모두 relation이 위, [3-5](ai-search-ml-first-call-decisions-2026-10-26.md)). 1차를 ML로 바꾼 뒤 같은 57개 질문에서 느린 10% 11.4 → 9.7초, 검색 1,000번 $1.52 → $1.40.

## 6. 2차를 에이전트로 — [에이전트 보고서](ai-search-agent-2026-10-26.md)

| **v1.16.3** | 한 번의 호출 | 77.0% | 4.0 | 1.19 | 9.5 | **5.1초** | **$1.40** |
| **v1.16.3** | 에이전트 / 3권 미만이면 다시 찾기 | 77.9 / 80.1% | 4.4 / 4.6 | 1.24 / 1.15 | 7.5 / 9.0 | 9.4 / 9.8초 | $1.85 / $1.96 |

→ 처음(v1.16.2)에는 에이전트가 8~10%p 이겼고 합치기는 맞는 카드가 1.5 → 4.9장. 그런데 같은 날 한 번의 호출에 「앞 질문들을 함께 찾는」 규칙을 더한 v1.16.3이 나와([3-6](ai-search-ml-first-call-decisions-2026-10-26.md)), 그 위에서 다시 재니 **차이가 흔들림(±5%p) 안으로 줄고**, 첫 글은 두 배 늦고, 돈은 32~40% 더 듦 → **켜지 않음**. 남은 이득은 합치기·이어 묻기(합치기 맞는 카드 2.7 → 4.2, 3권 미만 방식). 분명한 질문에서는 네 번 모두 되묻기 0번. **배운 것: 기준선이 바뀌면 다시 잰다 — 처음 숫자로 내보냈다면 비용만 늘었을 것.**

**그래서 되묻기만 한 번의 호출에** (고르기 JSON 맨 앞에 `ask` 칸, [보고서 10절](ai-search-agent-2026-10-26.md)): 전체 맞음 77.0 → 79.6%, **애매한 질문 69.4 → 77.8%, 맞는 카드 4.2 → 5.6장**, 분명한 질문 되묻기 0번, 되묻지 않은 질문의 첫 글 5.1 → 5.4초·비용 +3%. 에이전트에서 쓸모 있던 한 가지만 가장 싼 자리로 옮긴 것.

**운영에 넣은 조합 (v1.17.0)** — 되묻기 + Haiku 생각 끄기 + 지시문 캐시, 10만 권 위 두 번 평균([보고서 11절](ai-search-agent-2026-10-26.md)): 맞음 78.0 → **80.6%**, 애매한 질문 66.7 → **78.8%**, 틀린 카드 1.32 → **1.02장**, **첫 글 4.0 → 2.3초**, 출력 토큰 절반. 응답 시간을 단계별로 재 보니 검색은 0.45초뿐이고 나머지가 Haiku의 「생각」이라는 데서 출발. 생각을 꺼도 부정어·조건 질문(57문항 종류별)은 그대로였고, 대가는 카드 수(질문당 6.7 → 5.8장).

## 7. 한계 (포트폴리오에 같이 쓸 것)

- 질문 57개, 한 사람이 만든 질문. 채점은 사람 대신 Sonnet(같은 채점표를 모든 안에 씀).
- 대부분 안은 한 번씩만 돌림. 흔들림 폭(±3%p)은 두 안을 두 번 돌려 잰 값.
- 「○○ 같은 책」은 9개뿐이라 숫자가 크게 흔들릴 수 있음.
- 채점자 확인은 사람이 아니라 다른 모델(Opus)로 함: 카드 100장에서 맞음/틀림이 Sonnet과 88% 같음(Opus가 조금 후함). 사람이 직접 본 점수는 없음.
- 이어 묻는 질문 시험(대화 80개)은 rule·relation을 3번씩 돌림: 전체 맞음의 폭이 4%p 안팎이라 2%p 차이는 「비슷함」으로 읽어야 함. 관계마다 10~20개라 칸마다는 더 흔들림.
- 속도·비용은 로컬 PC에서 잰 값(2차 Haiku는 실제 API). 운영 앞뒤 값은 질문이 서로 달라 참고만.
- 3번 이어지는 대화(「위에 말한 두 개」, 「둘 섞은 느낌」)는 운영에서 사용자가 찾은 뒤 50개 시험을 만들어 고침(합치기 카드 0장 12 → 1 / 25, [3-6](ai-search-ml-first-call-decisions-2026-10-26.md)). 한 번씩 돌린 값이고, 「앞 질문 여러 개」는 신호 말 규칙으로 잡음(모델 아님).
- 에이전트 시험(6절)은 방식마다 두 번 돌림: 같은 한 번의 호출이 73.5 / 80.5%로 흔들려 5%p 안팎은 「비슷함」. 묶음마다 10~20개라 묶음 숫자는 더 흔들림(합치기 56 / 65%). 되묻기 답은 가상 사용자(Haiku)가 함 — 실제 사람이 되묻기를 어떻게 느끼는지는 재지 않음.
