# 1차 AI 호출을 작은 모델로 바꿀 수 있나: TF-IDF · KURE+분류기 · Cross-Encoder · Haiku (2026-10-25)

> 모든 전후 비교 숫자를 한곳에 모은 표: [AI 책 찾기 개선 기록 모음](ai-search-portfolio.md)

책첵 AI 책 찾기의 1차 호출(Haiku)은 질문을 읽고 검색 조건을 JSON으로 돌려줍니다. 이 중 **「정해진 칸에서 고르는」 부분을 LLM 없이 작은 모델로 할 수 있는지**, 같은 시험 질문으로 재 봤습니다. 운영 코드는 바꾸지 않았습니다.

## 1. 무엇을 대신하려는가

| 1차 답의 칸 | 성격 | 작은 모델로 |
|---|---|---|
| `notBook`·`titleLike`·`refersToShown` (예/아니오) | 고르기 | 대신할 수 있는지 잼 |
| 분야(큰 칸 22)·작은 칸 99·장르·나라·대상·수준·분위기·뺄 것 ([상세 사전](ai-search-eval/taxonomy2.json)) | 고르기 | 대신할 수 있는지 잼 |
| `keywords`·`core` (같은 뜻 낱말을 지어냄: 번아웃 → 지침, 소진) | 지어내기 | 분류기로는 못 함 → 이번 범위 밖 |

1차 호출의 구조화 출력은 MCP가 아니라 Anthropic API의 `output_config.format`(JSON 스키마)입니다. 백엔드가 순서를 정하고 모델은 정해진 칸만 채웁니다.

## 1-1. 말 정리 (이 실험의 구조)

```
질문 ─[KURE: 이미 만들어진 모델, 학습시키지 않음]→ 숫자 1,024개
     ─[고르는 부분: 우리가 학습시킴. 로지스틱 회귀 또는 작은 신경망]→ 칸마다 확률
     ─[문턱: 예 0.3 이상이면 고름]→ 답(소설 · 추리·스릴러 · 일본 …)
```

| 말 | 뜻 |
|---|---|
| KURE | 질문을 뜻이 담긴 숫자 1,024개로 바꾸는 한국어 모델. 운영 벡터 검색에 쓰는 것과 같음. 이 실험에서는 고정 |
| TF-IDF | KURE 대신 쓰는 다른 입력: 「어떤 낱말이 몇 번 나왔나」로 숫자를 만듦. 학습 없이 계산 |
| 로지스틱 회귀 | 고르는 부분 후보 ①. 고정된 임베딩 위에 선형 분류기를 얹는 것을 **선형 프로브(linear probe)**라고 부름. 칸마다 「숫자 1,024개 × 가중치」를 한 번 더해 확률로. 하나하나의 영향만 더함 |
| 작은 신경망 (MLP) | 고르는 부분 후보 ②. 전문 용어로 **다층 퍼셉트론(MLP, Multi-Layer Perceptron)**: 은닉층(hidden layer) 1개·512칸, 활성화 함수 ReLU, 드롭아웃 0.3, 출력은 칸마다 시그모이드(여러 칸을 고르는 multi-label), 손실 함수 BCE(이진 교차 엔트로피), 최적화 AdamW, 60에포크. 숫자 1,024개 → 중간 특징 512개 → 칸 점수. 중간 단계 덕분에 영향들의 조합까지 배움. 모양은 로지스틱 회귀 앞에 한 단계를 끼운 것이지만, 두 단계를 처음부터 함께 학습 |
| 동결 인코더 + 분류 헤드 | KURE(인코더)는 고치지 않고(frozen) 위의 분류 부분(head)만 학습하는 방식. KURE까지 고치면 **미세 조정(fine-tuning)** |
| 학습 | 정답이 달린 학습 질문을 보며 가중치를 맞춰 가는 것. 학습량이 다른 모델은 각각 백지에서 따로 학습(이어서 학습한 것이 아님) |
| 문턱 | 확률이 몇 이상이면 그 칸을 고를지. 칸마다 검증 질문 100개로 고름 |
| 학습 / 검증 / 시험 질문 | 학습 = 가중치를 정함, 검증(24묶음 100개) = 문턱을 고름, 시험(25~30묶음 600개) = 점수만 매김. 시험 질문은 학습·문턱 고르기 어디에도 안 씀 |
| F1 | 여러 칸을 고르는 문제의 점수. 「고른 칸 중 맞은 비율」과 「맞혀야 할 칸 중 고른 비율」을 함께 본 값(0~100%) |

| | 로지스틱 회귀 | 작은 신경망 |
|---|---|---|
| 계산 단계 | 1 | 2 |
| 배우는 가중치 (작은 칸 99개 기준) | 약 10만 | 약 57만 |
| 데이터가 늘 때 | 3,000개쯤에서 한계 | 더 오름 |
| 크기 · 속도 | 약 0.4MB · 1ms 안쪽 | 약 2MB · 1ms 안쪽 |

처음 계획은 로지스틱 회귀만이었고, 작은 신경망은 첫 결과가 낮아 원인을 찾으며 더한 비교 대상(5-1절부터). 두 방식 모두 단계마다 같은 시험으로 잼.

## 2. 데이터

- **질문 3,000개를 Sonnet이 만들고 정답 JSON을 닮** (하위 에이전트, API 키 없이). 씨앗을 먼저 만들어 12가지 유형(조건 하나·여럿, 빼 달라는 말, 부정어, 돌려 말하기, 부딪치는 조건, 막연한 질문, 「○○ 같은 책」, 책 찾기가 아닌 말, 제목만, 앞 책 가리키기)과 작은 칸 99개를 빠짐없이 나눠 담음. 사전 밖 값 0건. 도구: [`qgen_seeds.py`](../../scripts/aisearch/eval/qgen_seeds.py), 지시문 [`qgen-RULES.md`](../../scripts/aisearch/eval/qgen-RULES.md)
- **나누기**: 학습 = 1~24묶음 중 시험과 같은 질문을 뺀 2,306개, 시험 = 25~30묶음 600개(학습에 안 씀). 그리고 기존 평가 질문 57개(정답은 Sonnet이 [`qlabel-RULES.md`](../../scripts/aisearch/eval/qlabel-RULES.md)로 따로 닮).
- **Haiku 비교**: 같은 600개·57개에 Haiku가 같은 지시문으로 칸을 닮. 지금 운영 1차 Haiku는 이 칸을 내지 않으므로, 「Haiku에게 이 칸을 시키면」의 숫자.
- 실제 사용자 질문은 저장하지 않으므로(ADR-0152) 쓰지 않음.

|---|---|---|---|---|
| 책 찾기가 아닌 말 | 97.3% | 98.7% | **99.2%** | 98.7% |
| 제목만 친 것 | 97.0% | 97.3% | 98.3% | 100% |
| 앞의 책을 가리킴 | 98.5% | 99.7% | 99.8% | 100% |
| 빼 달라는 말이 있나 | 82.5% | 93.7% | 93.2% | 97.3% |
| 소설을 원하나 | — | 97.2% | 97.7% | 99.5% |
| 대상 | 70.7% | 84.7% | 86.5% | 83.5% |
| 수준 | 75.8% | 85.7% | 87.0% | 91.3% |
| 큰 칸 (F1) | 0% | 73.7% | **84.9%** | 93.4% |
| 작은 칸 99개 (F1) | 0% | 38.2% | 48.6% | **87.6%** |
| 장르 (F1) | 0% | 28.6% | 25.5% | **82.8%** |
| 분위기 (F1) | 0% | 72.7% | 67.5% | 92.0% |

평가 질문 57개도 순서가 같음(큰 칸 71.0 / 76.9 / 93.2%, 작은 칸 37.7 / 49.1 / 83.3%). 결과 파일: [`ai-search-eval/first-call/`](ai-search-eval/first-call/).

- 「늘 같은 답」= 아무것도 배우지 않고 가장 흔한 답만 낼 때. 예/아니오 칸은 원래 거의 늘 「아니오」라 이 기준이 높음.
- 「소설을 원하나」: 질문을 만든 Sonnet은 「주식 책」처럼 소설이 아닌 주제에도 `fiction: false`를 달았고, 칸 다는 지시문의 Haiku는 「소설 말고」라고 하지 않으면 비워 둠. 표기 습관 차이라 「소설을 원한다(true)인지」만 맞혔는지로 셈. 같은 지시문으로 단 57개에서는 Haiku와 Sonnet이 100% 같음.

**학습 데이터 양의 효과**: 질문 700개로 했을 때 KURE 큰 칸 48% → 2,306개로 85%.

## 5. 정리

- **대신할 수 있는 것** (5-5절에서 일부 바로잡음: 예/아니오 칸은 대신할 수 없었음): 예/아니오 칸(책 찾기 아닌 말·제목만·앞 책 가리키기)과 「소설을 원하나」, 「빼 달라는 말이 있나」는 KURE + 분류기가 Haiku와 1~4%p 안. 1ms 안쪽, 추가 모델 없음.
- **아직 못 하는 것**: 첫 판에서는 작은 칸·장르·분위기에서 Haiku가 크게 앞섰으나(작은 칸 49% vs 88%), 문턱 조정과 작은 신경망으로 차이가 줄어듦(작은 칸 79% vs 88%, 큰 칸 90% vs 93%, 5-1절). 장르는 아직 66% vs 83%.
- **그래서** (5-4절 전 판단): 1차 Haiku를 통째로 바꾸는 것은 지금은 손해 — **5-4절의 전체 흐름 시험에서는 바꿔도 최종 카드가 같았음.** 다만 큰 칸·예/아니오를 분류기로 먼저 정해 두고 Haiku가 실패하거나 늦을 때 대신 쓰는 길(대체 경로)은 바로 쓸 수 있는 수준.
- **Cross-Encoder**: 비교용으로만 잼(사용자 결정). 속도가 1차 Haiku보다 느려 운영 후보가 아님.

## 5-1. 첫 판을 다듬으면 (같은 시험 600개)

첫 판은 모든 칸에 같은 문턱(확률 0.35 이상이면 그 칸을 고름)을 썼습니다. 학습용 질문 중 100개(24묶음)를 떼어 칸마다 문턱을 고르고, 작은 신경망(KURE 숫자 1,024개 → 512 → 칸)도 시험했습니다.

| 칸 (F1) | 첫 판 (문턱 0.35) | 문턱을 칸마다 | 작은 신경망 + 문턱 | Haiku |
|---|---|---|---|---|
| 큰 칸 | 84.9% | 85.5% | **89.6%** | 93.4% |
| 작은 칸 | 48.6% | **79.2%** | 78.2% | 87.6% |
| 장르 | 25.5% | **65.8%** | 61.8% | 82.8% |
| 분위기 | 67.5% | 80.4% | **83.7%** | 92.0% |

- 가장 큰 효과는 **문턱 조정**: 드문 칸은 확률이 낮게 나와 0.35를 못 넘었던 것. 작은 칸 48.6 → 79.2%.
- **학습 질문 수**: 500 → 1,000 → 1,500 → 2,306개에서 큰 칸 54 → 74 → 81 → 85%, 작은 칸 2 → 13 → 28 → 49%로 아직 오르는 중 → 질문을 더 만들면 더 오를 것 [추론].
- 시도했지만 효과 없음: 책 27,227권의 벡터와 프로필 칸으로도 학습(책 소개와 질문은 말투가 달라 섞을수록 나빠짐, 문턱 고를 때 섞는 비율 0이 뽑힘), 작은 칸을 고른 큰 칸 아래에서만(77.1%로 조금 나빠짐).
- 드는 것: 작은 신경망은 칸당 학습 2~3분(PC), 예측은 1ms 안쪽, 크기 약 2MB.

## 5-2. 약한 칸을 노린 질문 3,000개를 더 넣으면 (같은 시험 600개)

칸별 학습 수와 시험 점수([`weak.json`](ai-search-eval/first-call/weak.json))로 약한 칸을 찾아(장르는 칸당 학습 질문 13개쯤, 작은 칸 18개쯤) 씨앗을 다시 짬: 장르 14개 × 약 80개, 작은 칸은 학습 수가 적고 점수가 낮을수록 많이, 나머지는 분위기·형식. Sonnet이 3,000개를 더 씀(31~60묶음). 시험 질문 600개는 그대로.

**학습량에 따른 점수** (로지스틱 회귀, 칸마다 문턱, F1):

| 학습 질문 | 큰 칸 | 작은 칸 | 장르 | 분위기 |
|---|---|---|---|---|
| 2,306 | 85.5% | 79.2% | 65.8% | 80.4% |
| 3,306 (+1,000) | 86.1% | 80.4% | 67.3% | 81.1% |
| 4,306 (+2,000) | 86.5% | 80.6% | 67.4% | 82.1% |
| 5,300 (+2,994) | 85.9% | 80.9% | 66.7% | 82.4% |

→ 1,000개씩 더해도 +0~1.5%p라 **거의 평평함**. 로지스틱 회귀는 질문 2,000~3,000개에서 거의 다 배움. 그래서 더 늘리지 않음(사용자 기준: 선형으로 오르면 6,000개까지).

**작은 신경망으로 5,300개를 학습하면** (F1):

| 칸 | 2,306개 신경망 | 5,300개 신경망 | Haiku |
|---|---|---|---|
| 큰 칸 | 89.6% | **90.7%** | 93.4% |
| 작은 칸 | 78.2% | **85.0%** | 87.6% |
| 장르 | 61.8% | **71.6%** | 82.8% |
| 분위기 | 83.7% | **88.4%** | 92.0% |

→ 로지스틱 회귀는 평평했지만 **신경망은 데이터가 늘수록 더 배움**: 작은 칸 +6.8, 장르 +9.8, 분위기 +4.7%p. Haiku와의 차이가 큰 칸 2.7, 작은 칸 2.6, 분위기 3.6%p로 좁혀짐. 장르만 11%p 차이가 남음. (큰 칸·작은 칸·장르는 60묶음 전 5,200개, 분위기는 5,300개로 학습.)

**드는 것**: 질문 3,000개 = Sonnet 하위 에이전트 30묶음(묶음마다 약 10만 토큰, 2.5~3분). 신경망 학습은 칸마다 PC에서 수 분, 예측은 1ms 안쪽.

## 5-3. 학습량 × 방식 (같은 시험 600개, F1)

약한 칸 질문을 1,000개 더 만들어(61~70묶음, Sonnet) 1,000개 단위로 두 방식을 같은 방법으로 잼: 학습량마다 백지에서 따로 학습 → 검증 100개로 문턱 → 시험 600개.

| 학습 질문 | 큰 칸 LR / MLP | 작은 칸 LR / MLP | 장르 LR / MLP | 분위기 LR / MLP |
|---|---|---|---|---|
| 2,306 | 85.5 / 89.5 | 79.2 / 78.5 | 65.8 / 61.5 | 80.4 / 83.7 |
| 3,306 | 86.1 / 90.6 | 80.4 / 82.6 | 67.3 / 67.3 | 81.1 / 86.2 |
| 4,306 | 86.5 / **91.0** | 80.6 / 84.2 | 67.4 / 68.9 | 82.1 / 86.8 |
| 5,300 | 85.9 / **91.0** | 80.9 / 83.9 | 66.7 / **71.7** | 82.4 / **88.5** |
| 6,298 | 87.3 / 89.8 | 81.6 / **86.5** | 70.7 / 71.0 | 84.6 / 86.2 |
| (Haiku) | 93.4 | 87.6 | 82.8 | 92.0 |

LR = 로지스틱 회귀, MLP = 작은 신경망. 같은 학습량에서 MLP가 대체로 2~6%p 높음(2,306개의 작은 칸·장르만 LR이 높음).

**읽는 법**
- MLP는 2,306 → 4,306개에서 크게 오르고(작은 칸 +5.7, 장르 +7.4%p) 그 뒤로는 ±1~2%p 안에서 오르내림 → **4,000~5,000개에서 거의 다 배움**. 작은 칸만 6,298개에서도 +2.6%p.
- LR은 6,298개에서 조금 오름(장르 +4%p) — 61~70묶음이 장르를 많이 담은 영향 [추론].
- 선형으로 오르지 않으므로 질문을 더 만들지 않음(사용자 기준).
- 최고 점수 기준 Haiku와의 차이: 큰 칸 2.4, 작은 칸 1.1, 분위기 3.5, 장르 11.1%p.

**드는 것**: 질문 4,000개 추가 = Sonnet 하위 에이전트 40묶음(묶음마다 약 10만 토큰). MLP 학습은 학습량마다 PC에서 1~3분, 예측 1ms 안쪽.

## 5-4. 전체 흐름에 넣어 최종 카드로 (질문 57개, 2차 Haiku까지, 같은 채점표)

1차 호출만 바꾸고 나머지(후보 → 2차 Haiku가 고름 → Sonnet 심사)는 같게 둠. 칸을 쓰는 안은 모두 PFx 방식(칸 맞는 책을 앞으로 + 「소설 말고」·빼 달라는 칸은 뒤로, [개선 보고서 6-4절](ai-search-improvement-2026-10-25.md)). LR·MLP는 학습 질문 6,298개 전부로 학습.

| 안 | 1차가 만드는 검색어 | 1차가 고르는 칸 | 1차에 LLM | 맞음 | 아주 맞음 | 틀린 카드 | 전부 맞은 질문 |
|---|---|---|---|---|---|---|---|
| P (지금 운영) | Haiku | — | 씀 | 95% | 71% | 0.37 | 46 |
| H | Haiku | Haiku | 씀 | 94% | 70% | 0.51 | 43 |
| HM | Haiku | MLP | 씀 | 94% | 69% | 0.47 | 44 |
| **M** | 질문 낱말 그대로 | MLP | **안 씀** | **96%** | **72%** | **0.30** | 45 |
| L | 질문 낱말 그대로 | LR | 안 씀 | 93% | 71% | 0.53 | 40 |
| **MT** | 질문 낱말 + 책 프로필 주제어 중 가까운 것 | MLP | **안 씀** | **96%** | **72%** | **0.30** | **47** |

- **1차 Haiku 없이도 최종 카드가 나빠지지 않음**: M·MT가 아주 맞음 72%·틀린 카드 0.30으로 P(71%·0.37)와 흔들림(±3%p) 안에서 같거나 조금 나음.
- 이유 [추론]: 검색어를 지어내지 않아도 **벡터 검색(KURE)이 같은 뜻의 다른 말을 이미 잡고**, 2차 Haiku가 후보를 다시 읽어 거르기 때문. 1차의 몫이 작았음.
- LR은 틀린 카드가 0.53으로 가장 많음 — 칸이 덜 정확해 거르기가 빗나감. 칸을 쓸 거면 MLP.
- H(Haiku 칸)는 이번에 70%로, 앞서 Sonnet 칸으로 잰 PFx(74%)보다 낮음 — 흔들림 안이고 칸 품질 차이일 수 있음.
- 유형별(질문 4~9개라 흔들림 큼): 「○○ 같은 책」 P 36% → M 46%·MT 42%, 조건 81 → 88/84%, 두 주제 81 → 68/66%(나빠짐).
- 이번 평가 질문 57개는 모두 책 찾는 질문이라, 1차가 하는 「책 찾기가 아닌 말·제목만·앞 책 가리키기」 판단은 여기서 재지 않음 → **5-5절에서 따로 잼: 분류기는 이 판단을 못 함(MLP 58.5%, Haiku 97.8%).**

**두 번째로 돌림** (같은 후보, 2차 Haiku만 다시 — 흔들림 확인):

| 안 | 아주 맞음 1회 / 2회 / 평균 | 틀린 카드 1회 / 2회 / 평균 | 전부 맞은 질문 1회 / 2회 |
|---|---|---|---|
| P (지금 운영) | 71 / 73 / **72%** | 0.37 / 0.37 / **0.37** | 46 / 46 |
| M (LLM 없음) | 72 / 72 / **72%** | 0.30 / 0.42 / **0.36** | 45 / 42 |
| MT (LLM 없음) | 72 / 71 / **71.5%** | 0.30 / 0.40 / **0.35** | 47 / 46 |

→ 두 번 평균으로 **세 안이 같음**(아주 맞음 차이 0.5%p, 틀린 카드 차이 0.02장). 1회에서 M·MT가 「조금 나아 보인」 것은 흔들림이었음. 결론은 「1차 Haiku 없이도 최종 카드가 **같다**」.

**드는 것 (1차 호출만)**

| | Haiku 1차 (P·H) | 분류기 1차 (M·MT) |
|---|---|---|
| 시간 | 1~2.4초 (1단계 측정 최대 2.4초) | 질문 벡터는 이미 만듦 + MLP 1ms 안쪽 + 주제어 찾기 PC 0.3ms(서버 수 ms) |
| 비용 | 검색당 약 $0.0002 (전체의 약 15%) [설정 단가 추정] | 0 |
| 장애 지점 | API 호출 1번 더 | 없음 |

**한계**: 한 번씩만 돌림(흔들림 ±3%p), 질문 57개, 질문 쪽 정답·학습 질문 모두 Sonnet이 만든 것.

## 5-5. 길 나누기만 따로: 책 찾기 아님 · 제목만 · 앞 책 가리킴 (질문 400개)

1차 호출의 다른 일은 질문을 길로 나누는 것: 책 찾기가 아닌 말이면 검색하지 않음, 제목·저자만이면 「직접 찾기」로 안내, 앞에서 보인 책을 가리키면 그 책들 안에서 다시 고름. 틀리면 결과가 크게 바뀌므로, 헷갈리는 질문을 일부러 섞어 따로 잼. Sonnet이 유형마다 100개(책 찾기 아님 · 제목·저자만 · 앞 책 가리킴 · **헷갈리는 보통 질문**: 「한강 소설 추천해줘」 「채식주의자 같은 책」 「심리학」 「도서관에서 빌리기 좋은 두꺼운 소설」). 섞어서 앞 대화 없이 한 줄씩. 지시문: [`route-RULES.md`](../../scripts/aisearch/eval/route-RULES.md).

| | 전체 | 책 찾기 아님 | 제목만 | 앞 책 가리킴 | 보통 질문 | 보통 질문을 「책 찾기 아님」으로 막음 |
|---|---|---|---|---|---|---|
| **Haiku (운영 1차 지시문 그대로)** | **97.8%** | 100% | 97% | 94% | 100% | 6 |
| MLP (학습 6,298개) | 58.5% | 32% | 54% | 49% | 99% | 1 |
| LR (학습 6,298개) | 37.0% | 14% | 17% | 18% | 99% | 0 |

- **분류기는 길 나누기를 대신하지 못함.** 학습 질문 6,298개 중 이 세 유형이 각각 40~57개(1% 미만)라, 거의 늘 「보통 질문」이라고 답하게 배움.
- **바로잡음**: 3절의 「책 찾기 아닌 말 98~100%」는 시험 600개 중 97%가 「아니오」라 늘 「아니오」만 해도 97%가 나오는 칸이었음. 그 숫자로 「대신할 수 있다」고 한 판단(5절, 5-4절 끝)은 틀렸음. 이 유형만 모아 재면 32~54%.
- Haiku가 틀린 9개 중 6개는 「앞 책 가리킴」을 「책 찾기 아님」으로 본 것: 앞 대화 없이 「다섯 번째 책은 누구한테 맞아?」만 받음. 운영에서는 앞 대화(최대 5턴)를 함께 받으므로 이 경우는 맞힐 것 [추론].
- **판단**: 이어 묻는 질문(2번째 이후)은 앞 대화와 함께 Haiku에게. 첫 질문을 분류기로 하려면 길 나누기용 질문을 따로 많이 학습시켜야 함(다음 실험).
