# AI 책 찾기 2차 단계 규칙 점검 (2026-10-27)

사용자 요청(2026-10-27): "규칙을 총체적으로 검증해야 할 것 같아", "검증하는게 성능테스트 이외에 일괄적인 구성이라던가 그런것도". 2차 단계(후보 30권에서 고르고, 되묻고, 글을 쓰는 단계)를 정하는 **지시문 규칙(P·A)** 과 **코드 규칙(C)** 을 한 표에 모으고, 서로 부딪히는 곳·겹치는 곳·빈 곳을 찾은 뒤, 규칙마다 확인하는 시험 문항을 붙였습니다. 시험 결과는 맨 아래 「시험 결과」 절.

- 지시문: `backend/.../flow/Prompts.java`의 `PICK_SYSTEM`(늘 씀)과 `PICK_ASK_SYSTEM`(되묻기를 켜고 되물어도 되는 질문일 때 = `PICK_SYSTEM` + A1~A3)
- 코드: `AiSearchFlow`, `MlFirstCall`, `EarlierTopics`, `CandidateQuery`
- 출처의 날짜와 말은 사용자 결정. 시험 문항 묶음 이름은 `scripts/aisearch/eval/rules_suite.json`의 `rule` 값

## 2. 부딪히는 곳·겹치는 곳·빈 곳

| # | 종류 | 내용 | 처리 |
|---|---|---|---|
| 1 | 부딪힘 | P2 「억지로 고르지 않는다」 ↔ P9 「8권까지 채운다」 | P9에 「fit 2 이상만」, 「조건과 반대인 책으로는 채우지 않는다」를 붙여 경계를 정함. 채운 탓에 틀린 카드가 늘지 않는지 `neg`·`clear`의 틀린 카드로 확인 |
| 2 | 부딪힘 | A1(가) 「낱말 하나에 뜻이 여럿이면 되묻는다」 ↔ A3 「흔한 뜻이 하나로 모이면 되묻지 않는다」 — 「사진」은 어느 쪽인지 모델마다 다르게 읽음 | 「후보 분야」 줄(C4)을 판단 근거로 줌. 경계 양쪽을 지시문 예시에 없는 낱말로 시험(`ask_yes` 16개, `ask_no` 10개) |
| 3 | 빈 곳(**고침**) | 되묻기 다음 턴은 코드가 `PICK_SYSTEM`을 쓰는데, 「되물은 말」이 무엇인지 설명은 `PICK_ASK_SYSTEM`(A3)에만 있었음 → 그 턴의 모델은 설명 없이 「되물은 말」을 봄 | 설명을 P16으로 옮기고 A3의 중복 줄을 뺌(커밋 7aba5962) |
| 4 | 겹침 | 합치기 말에 되묻지 않기: 지시문 A3 + 코드 C3 | 둘 다 둠: 코드는 「두 개」, 「둘 다」, 「섞은」, 「합친」, 「모두」만 잡으므로 다른 말(「같이 다룬 거」, 「짬뽕」)은 지시문이 맡음. `combine`에 코드가 못 잡는 말을 넣어 시험 |
| 5 | 겹침 | 번호·fit·8장·글자 수: 지시문 + 코드 | 의도된 이중 안전장치. 지시문이 어겨도 화면에는 안 나감 |
| 6 | 빈 곳 | 1차 ML이 한 낱말 아닌 짧은 주제(「사진 책」, 「음악 이야기」)를 「책 찾기 아님」으로 나누면 C1 고정 되묻기(상관없는 예시)로 감 | 이번엔 고치지 않음. `notbook`에 「사진 책」 같은 문항을 넣어 실제로 일어나는지 봄 |
| 7 | 빈 곳 | 3낱말 이상 애매한 질문(「요즘 읽을 만한 거」)에는 「후보 분야」 줄이 없음 | 지시문 A1(다)만으로 판단. `ask_yes`에 한두 개 넣어 봄 |
| 8 | 부딪힐 수 있음 | P12(묻지 않은 연도 금지) ↔ `period` 질문(「요즘 나온」) | P12에 시기 질문 예시가 있음. 자동 검사는 시기 낱말이 없는 질문에서만 연도를 셈 |
| 9 | 표현 | A2 「직접 적어 달라는 뜻」을 모델이 고르는 말로 씀 | 자동 검사: 되묻는 말에 「적어」, 「말씀」, 「알려」, 「써」 중 하나가 있는지 |
