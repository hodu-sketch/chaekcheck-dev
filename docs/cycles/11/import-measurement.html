Java 옵션: 무엇이고 효과는

비교한 두 옵션은 코드를 바꾸지 않고 실행할 때 Java에 붙이는 설정입니다. 측정 도구가 모든 실행에 붙인 옵션도 함께 적었습니다.

옵션구분무엇을 하나효과와 쓰는 법

힙을 얼마나 줄일 수 있나

힙 크기별 내보내기 결과

6GB에서 시작해 4 → 3 → 2 → 1GB로 내리며, 처음 실패한 값에서 멈췄습니다. 칸의 숫자는 전체 시간(분)입니다. 진한 칸이 끝까지 된 가장 작은 힙입니다. compact + Java 옵션은 결정 뒤 1GB와 2GB만 따로 쟀고, 2GB 실행은 도중에 테스트를 함께 돌려 시간이 늘어났습니다.

힙 최고는 힙 풀 최고 사용량의 합이라 -Xmx보다 클 수 있습니다. 살아 있는 데이터는 전체 GC 뒤 값, 전체 GC가 없으면 Remark 뒤 값(상한)입니다.

compact + Java 옵션 2GB가 더 걸린 이유

compact 2GB는 21분 17초, 같은 2GB에 Java 옵션 둘을 붙인 실행은 36분 42초였습니다. 단계마다 비교하면 Java 옵션과 상관없는 DB 단계(번호 잇기, 새 표 쓰기)도 1.6~1.9배 느려졌고, GC 정지 시간은 거의 같습니다. 그래서 대부분은 그 시간(19:01~19:38)에 같은 PC에서 돌던 다른 일 탓으로 봅니다: 기본값 변경 테스트(19:20쯤)와 사이클 12의 전체 빌드(테스트 686개)가 겹쳤습니다. 옵션 자체의 비용은 Java CPU가 약 750초 늘어난 것으로, 같은 글자 합치기가 문자열을 해시해 찾는 일입니다. compact는 글자를 이미 한 벌씩 모아 두어 합칠 것이 거의 없습니다(메모리 약 2% 감소). 그래서 compact에는 옵션을 붙이지 않습니다.

단계누가 하는 일compact 2GB+ Java 옵션 2GB배수

시간 단계는 분:초, GC 정지는 초, Java CPU는 초입니다. 정확한 옵션 비용은 PC가 조용할 때 다시 재야 알 수 있습니다.
