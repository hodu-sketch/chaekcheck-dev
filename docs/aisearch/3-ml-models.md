## 요약

- **두 단계**: ① 한국어 문장 임베딩 모델 **KURE-v1**(학습하지 않고 그대로, int8로 줄여 씀)이 질문을 1,024개 숫자로 바꾸고, ② 그 위에 우리가 학습한 **은닉층 1개짜리 MLP**들이 판단한다.
- ②는 **1차 모델 파일 하나에 머리(head) 12개**(길 나누기 5갈래 1개 + 칸 11개)와 **관계 분류기 파일 하나**(이어 묻는 질문의 관계 7가지)다. 머리마다 은닉층을 따로 가진 독립 모델이다.
- 이름 붙이면 「고정된 사전학습 인코더 + 작업별 MLP 머리」, 곧 전이학습의 **특징 추출(feature extraction)** 방식. 앙상블·스태킹·Wide & Deep은 쓰지 않았다.
- **로지스틱 회귀는 기준선**(같은 벡터 위 linear probe)으로만 함께 돌렸고, MLP가 확실히 나아 운영에는 MLP만 넣었다(학습 6,298개에서 작은 칸 F1 81.6 → **86.5%**).
- **학습 데이터는 Claude Sonnet이 만든 질문과 정답**(합성 데이터). 1차 단계의 Haiku 호출(1~2.4초)을 없앴다(v1.16.0).
- 가장 큰 교훈: **클래스 불균형**. 세 갈래가 학습 질문의 1% 미만일 때 길 나누기 58.5%, 갈래마다 고르게 400개를 더하자 **94.5%**.

| 모델 | 입력 → 출력 | 학습 | 시험 결과 | 운영 |
|---|---|---|---|---|
| KURE-v1 (int8, 낱말표 88,446조각) | 질문 → 1,024 숫자(길이 1) | 하지 않음 | 원래 모델과 벡터 닮음 PC 0.989 · 운영 서버 0.988, 2.2GB → **385MB** | v1.15.0~, 임베딩 서버 |

## 1. 왜 두 단계인가

```
질문 「출근길에 가볍게 읽을 과학책」
   │ ① KURE-v1 (학습 안 함)
   ▼
1,024차원 벡터 ── ② 길 나누기 MLP → 「보통 질문」
              ├─ ② 칸 MLP 11개   → 큰 분야=과학, 독자=교양 …
              └─ (이어지는 질문) ③ 관계 MLP → 「continue」 …
```

(위 출력 값은 형태를 보이는 예이며, 이 질문으로 실제 모델을 돌린 값은 아닙니다.)

- ①은 수억 문장으로 이미 배운 「문장의 뜻을 좌표로」, ②③은 우리 데이터 몇천 개로 배운 「그 좌표로 우리 질문에 답하기」. 한국어 뜻을 처음부터 배우려면 수백만 개가 필요해, 뜻은 기성 모델에 맡기고 작은 판단만 배웠다.
- **전이학습(transfer learning)** 가운데 인코더를 얼려(frozen) 두고 위에 분류기만 얹는 **특징 추출**. 인코더까지 함께 학습하는 미세조정(fine-tuning)은 하지 않았다. 인코더 위에 선형 분류기만 얹어 재는 것을 **linear probe**라고 하며, 우리가 비교한 「KURE + 로지스틱 회귀」가 이것이다.

## 2. ① KURE-v1

- 고려대 NLP&AI Lab의 한국어 검색용 임베딩(`nlpai-lab/KURE-v1`, MIT). BAAI/bge-m3를 한국어 데이터로 미세조정한 Transformer **인코더**(모델 카드, PC 사본 `chaekcheck-data\ml\hf`). 운영 ONNX 그래프는 24층 끝의 **첫 토큰(CLS) 벡터**를 길이 1로 나눠 내보냄 → 두 벡터의 내적 = **코사인 유사도**([1-how-it-works 3-4절](1-how-it-works.md#3-4-모델-폴더-파일)).
- **바이인코더**: 질문과 책을 따로 벡터로 만든다. 책 81,078권 벡터는 미리 만들어 두고(`book-vectors.bin`, 83,996,822바이트, int8 × 줄마다 scale) 질문 벡터와 내적만 한다([4-4절](1-how-it-works.md#4-4-가까운-책-nearest)). 둘을 한꺼번에 넣어 점수를 내는 **크로스인코더**(bge-reranker-v2-m3)도 쟀지만 질문 하나 9.2초, 학습 없이 큰 칸 F1 37.5%라 버렸다([1차 호출 보고서 4-1절](reports/2026-10-25-first-call-models.md)).
- 운영용으로 줄인 것([임베딩 보고서 4·5절](reports/2026-10-25-embedding.md)): 원래 토크나이저 조각 25만 개 중 한글·라틴·숫자·흔한 기호 **88,446개**만 남기고, 가중치를 **int8(채널별) 양자화**, ONNX로 → **2.2GB → 385MB**, 질문 하나 54ms(PC), 원래와 벡터 닮음 **0.989**(PC) / 0.988(운영 서버 임시 컨테이너). 운영은 이 모델을 따로 둔 작은 EC2(임베딩 서버)에서 돌린다([1-how-it-works 3-5절](1-how-it-works.md#3-5-임베딩-서버-embed-service)). 질문 하나: 운영 서버의 임시 Python 컨테이너에서 중간 106ms(임베딩 보고서 5절), 임베딩 서버에서 60~68ms([6-aisearch 7-1절](../maintenance/6-aisearch.md)).

## 3. ② MLP 머리

모든 머리가 같은 뼈대(`scripts/aisearch/eval/export_first_call2.py`의 `mlp_model`, 관계 분류기는 `rel_train.py`의 `mlp`):

```python
nn.Sequential(nn.Linear(1024, 512), nn.ReLU(), nn.Dropout(0.3), nn.Linear(512, n))   # 관계 분류기는 Linear(4096, 512)
# AdamW(lr=1e-3, weight_decay=1e-4), 미니배치 64, 60 epoch, torch.manual_seed(0)
```

- 가중치 수: 1차 머리 하나 = 1,024×512 + 512 + 512×n + n ≈ 53만(작은 칸 99개 머리는 약 58만). 관계 분류기 = 4,096×512 + … ≈ 210만. 파일은 1차 25,824,240바이트 + 관계 8,405,204바이트 = 약 34MB.
- **머리마다 은닉층을 따로** 가진다(은닉층을 공유하는 멀티태스크 학습이 아님). 칸 하나를 다시 학습해도 다른 칸이 흔들리지 않게 한 실용적 선택.

머리 종류(운영 모델 파일 머리 JSON, [1-how-it-works 3-4절](1-how-it-works.md#3-4-모델-폴더-파일) 표):

| 종류 | 머리 | 마지막 층 · 손실 | 판정 (`FirstCallModel.route`·`labels`·`label`) |
|---|---|---|---|
| route | 길 나누기 1개(5갈래: 책 찾기 아님·제목만·앞 책 가리킴·책첵 사용법 질문·보통 질문) | softmax · CrossEntropy | 가장 높은 갈래, 단 「보통 질문」이 아니면 확률 **0.55** 이상일 때만 |
| multi | 7개(분야 22·작은 분야 99·장르 14·형식 7, 빼 달라는 분야 22·작은 분야 99·장르 14) | 출력마다 sigmoid · BCEWithLogits | 칸마다 정한 문턱 이상인 칸을 **칸 순서대로(확률 순 아님)** 앞 2개까지 |
| single | 4개(소설 여부 3·나라 9·독자 대상 8·수준 4) | softmax · CrossEntropy | 가장 높은 것 |

- multi 머리의 출력 하나는 「은닉층이 만든 512개 특징 위의 로지스틱 회귀」이고, 99칸 머리는 이것 99개를 한꺼번에 돌리는 **다중 라벨 분류**. route·single은 은닉층 위의 **다항 로지스틱 회귀**와 같다.
- 「분위기(mood)」 칸은 실험(보고서 5-1~5-3절)에서만 쟀고 운영 모델에는 머리가 없다(`predict_eval.py`의 `MULTI`·`SINGLE`, 운영 머리 JSON).

## 4. 확률을 결정으로: 문턱

- **칸별 문턱**: 학습 질문 가운데 dev로 떼어 둔 질문에서 0.05~0.65를 0.05씩(`np.arange(0.05, 0.7, 0.05)`) 바꿔 **F1이 가장 높은 값**을 골랐다 → 분야 0.10, 작은 분야 0.30, 장르 0.25, 형식 0.65, 빼 달라는 분야 0.50, 빼 달라는 작은 분야·장르 0.05. 데이터가 정한 정밀도·재현율의 균형점. (전에 「0.05~0.70」으로 적었으나 스크립트의 범위는 0.65까지.)
- **길 나누기 tau 0.55**(파일 값 0.5499999999999999): 「책 찾기 아님」·「책첵 질문」으로 잘못 보내면 검색을 하지 않아 책을 하나도 못 받고, 「보통 질문」으로 잘못 보내면 조금 덜 맞을 뿐 → **오분류 비용이 비대칭**. dev에서 「책·제목·앞 책 질문을 책 찾기 아님·책첵 질문으로 보낸 수」가 1 이하인 tau 가운데 정확도가 가장 높은 값을 0.30~0.95(0.05씩)에서 골랐다(`route5.py`·`route5b.py`). 비용 민감 판정이자, 확신이 없으면 안전한 기본값으로 가는 **거부 선택(reject option)**의 변형.

## 5. ③ 관계 분류기

이어지는 질문과 앞 질문의 관계 7가지: refers(앞 책 안에서) · ask_one(앞 책 한 권을 물음) · continue(조건 더하기) · shift(주제 옮기기) · feedback(앞 결과에 반응, 다시 찾기) · new(새 주제) · none(책 찾기 아님). 관계마다 검색을 어떻게 바꾸는지는 [1-how-it-works 4-3절 (바)](1-how-it-works.md#4-3-ml-1차-ml) 표.

```
입력 4,096 = [ v(지금 질문), v(앞 질문), v(앞 질문 + " " + 지금 질문), v(지금) ⊙ v(앞) ]
```

- ⊙(원소별 곱)은 두 문장이 같은 방향인 차원을 키워 「무엇이 같고 다른가」를 직접 보여 준다. 문장 쌍 분류의 고전 꼴(InferSent, Conneau et al. 2017: `[u, v, |u−v|, u⊙v]`)에서 `|u−v|` 대신 이어 붙인 문장의 벡터를 넣어, 「판타지인데 → 서정적인 거」처럼 붙여 읽어야 뜻이 나오는 경우를 잡게 했다.
- 4,096 → 512 → 7, softmax · CrossEntropy. 관계당 학습 100 / 200 / 300 / 399쌍(시드 3개 평균) → 시험 700쌍 93.8 / 96.0 / 95.9 / **96.4%**(200쌍 뒤 평평). 가장 약한 관계 continue 91%, new 94%. 운영 파일은 399쌍·시드 0 모델(`export_follow_up.py`).
- 전체 흐름(대화 80개, 2차 Haiku까지): 처음 한 번 돌린 값은 손 규칙 대비 맞음 72.2 → 75.4%, continue 64 → 79%([넣은 것과 뺀 것](reports/2026-10-26-ml-first-call-decisions.md) 3-4절, #24). **3번씩 다시 돌린 평균은 74.3 → 76.2%(규칙 쪽 흔들림 4.2%p 안), continue 67.4 → 76.2%**로 바로잡혔다(같은 보고서 3-5절). 흔들림을 넘는 것은 continue와 카드 없는 답(12~14 → 7~9 / 70)이다.

## 6. 학습 데이터: LLM이 만든 정답

- 질문과 정답 모두 Claude Sonnet이 만든 **합성 데이터**: 칸 학습 질문 6,298개, 길 나누기 갈래당 600개, 짧은 장르·분위기 질문 300개, 관계 쌍 7 × 400(new 399). 시험 질문은 따로 쓰고 학습과 겹치지 않게 막았다(칸: 학습 1~24묶음에서 시험과 같은 질문을 뺌, 시험 25~30묶음 600개 / 길 나누기: `avoid.txt` / 관계: 시험 쌍의 첫 질문은 학습에 없음).
- 큰 모델(LLM)의 판단을 작은 모델에 옮긴 셈이라 넓게는 **증류**에 가깝지만, 확률(soft label)이 아니라 정답 하나(hard label)를 배웠으므로 「LLM 라벨로 학습」이 정확한 말.
- 학습량 곡선(작은 칸 99개 F1, 로지스틱 / MLP): 2,306개 79.2 / 78.5% → 4,306개 80.6 / 84.2% → 6,298개 81.6 / **86.5%**. 적을 때는 비슷하고, 많아질수록 용량이 큰 MLP가 앞선다([1차 호출 보고서 5-3절](reports/2026-10-25-first-call-models.md)).

**클래스 불균형** ([1차 호출 보고서 5-5·5-6절](reports/2026-10-25-first-call-models.md)):

| 학습 데이터 | 길 나누기 맞음(시험 400개) |
|---|---|
| 칸 학습 질문만 6,298개(세 갈래가 각 40~57개, 1% 미만) | MLP 58.5%, 로지스틱 37.0% (Haiku 97.8%) |
| 갈래마다 400개 고르게 더함(4갈래) | **MLP 94.5%**, 로지스틱 93.5% |

- 처음 데이터의 97%가 「보통 질문」이라, 거의 늘 「보통 질문」이라 답하도록 배웠다. 「책 찾기 아님 98~100%」라던 숫자도 「늘 아니오여도 97%」인 착시였다 → 불균형 데이터에서는 **정확도 대신 갈래별 재현율·F1**을 본다.

## 7. 로지스틱 회귀와의 비교 (기준선)

| 칸 맞히기 F1(시험 600개) | 큰 칸 | 작은 칸 99개 | 장르 | 분위기 |
|---|---|---|---|---|
| 질문 낱말 빈도(TF-IDF) + 로지스틱 회귀 | 73.7% | 38.2% | 28.6% | 72.7% |
| KURE + 로지스틱 회귀, 모든 칸 문턱 0.35 | 84.9% | 48.6% | 25.5% | 67.5% |
| KURE + 로지스틱 회귀, 칸별 문턱 | 85.5% | 79.2% | 65.8% | 80.4% |
| KURE + MLP, 칸별 문턱 (학습 2,306개) | 89.6% | 78.2% | 61.8% | 83.7% |
| KURE + MLP, 약한 칸 질문 3,000개 더함(학습 5,200~5,300개) | **90.7%** | **85.0%** | **71.6%** | **88.4%** |
| KURE + MLP, 학습 6,298개(운영 판과 같은 양) | 89.8% | 86.5% | 71.0% | 86.2% |
| Haiku(같은 지시문, 참고) | 93.4% | 87.6% | 82.8% | 92.0% |

- 넷째 줄은 전에 「89.6 / 79.2 / 65.8 / 83.7%」로 적었는데, 작은 칸·장르 값이 로지스틱 회귀 + 칸별 문턱 줄의 값이었다. 보고서 5-1절 표대로 고치고 그 줄을 따로 넣었다. 여섯째 줄은 보고서 5-3절 표에서 더했다.
- 데이터가 많고 갈래가 고를 때(길 나누기 94.5 vs 93.5%)는 차이가 작고, 라벨이 많고 섬세한 칸에서 MLP가 확실히 낫다. 선형 모델은 벡터 공간을 초평면으로만 자르고, 은닉층이 있으면 굽은 경계를 그린다.
- 평가 때 MLP를 **시드 3개**로 학습해 평균을 낸 실험이 있다(관계 분류기 `rel_train.py`, 길 나누기 `route5.py`·`route5b.py`). 앙상블이 아니라 흔들림을 재는 반복 실험이고, 운영에는 시드 0 모델 하나만 넣었다.

## 8. 운영에서 돌리는 법

- PyTorch 없이 **Java로 계산**: 가중치를 `CCFC1` 머리 + JSON 설명 + float32 배열 파일로 내보내고(`export_first_call2.py`, `export_follow_up.py`), `FirstCallModel.outputs`가 머리마다 행렬곱 두 번(512×1,024, n×512), ReLU, softmax/sigmoid를 직접 한다. `MlFirstCall.plan`이 머리 12개와(이어 묻기면) 관계 분류기를 부른다. 계산 시간: PC에서 1ms 안쪽, 운영 서버 로그 단계 `ml` 중간값 12ms(검색 8번, v1.18.0, [첫 글 시간 보고서 1절](reports/2026-10-27-latency.md)). 질문 벡터 만들기(운영 `encode` 중간값 146ms)가 훨씬 길다.
- **학습–서빙 차이 점검**: 학습은 원래 KURE(float32) 벡터, 운영은 int8 ONNX 모델 벡터 → 내보내기 스크립트가 같은 시험 질문을 두 벡터로 다시 잰다. 운영 파일의 점검 기록(`aisearch-model\first-call-v2-2026-10-26\first-call-check.json`, 시드 0 모델 하나, fp32 → int8):

| 머리 | 지표 | fp32 → int8 |
|---|---|---|
| route (시험 600개) | 맞은 비율 / 보통 질문을 막은 수 | 93.7 → 93.5% / 2 → 1 |
| field / subfield / genre / form | F1 (시험 600개) | 89.9 → 90.3% / 87.4 → 87.0% / 69.5 → 69.5% / 76.5 → 77.4% |
| ex_field / ex_subfield / ex_genre | F1 | 37.1 → 37.7% / 50.0 → 52.6% / 68.1 → 68.1% |
| fiction / country / audience / level | 맞은 비율 | 90.0 → 89.7% / 98.0 → 97.8% / 85.2 → 84.7% / 87.0 → 86.7% |

  - 전에 이 줄에 「길 나누기 93.9 → 93.5%」로 적었는데, 93.9%는 보고서의 fp32 값(#23-1)이고 같은 시드 0 파일의 fp32 점검 값은 93.7%다. 칸 머리 숫자가 5-3절 표(89.8 / 86.5 / 71.0%)와 조금 다른 것은 한 모델(시드 0)·한 번 학습 값이라서다.
- 쓰임(자세한 계산은 링크한 절):
  - 길 → `SITE`면 Haiku가 책첵 안내로 답, `NOT_BOOK`이면 낱말 하나짜리가 아닐 때 모델 호출 없이 고정 되묻기, `TITLE_LIKE`면 제목 비교 뒤 보통 검색, `REFERS_SHOWN`이면 앞 책과 그 이웃을 후보 앞에([4-5절](1-how-it-works.md#4-5-길에-따라-여기서-끝나는-경우), [4-6절](1-how-it-works.md#4-6-앞-책이름-댄-책-neighbours)).
  - 칸 → RRF 점수에 「질문 칸과 `book-profiles.tsv`의 책 칸이 같은 수 × 0.004」를 더하고, 빼 달라는 칸·「소설 아님」에 걸리는 책은 맨 뒤로([4-9절](1-how-it-works.md#4-9-합치기-mix)).
  - 관계 → 낱말(자기 것 / 앞 질문과 이은 것), 검색 벡터(지금 질문 / 「앞 + 지금」), 칸을 덮을지를 정함([4-3절 (바)](1-how-it-works.md#4-3-ml-1차-ml)).
- 효과(v1.16.0, 같은 57문항 두 번 평균): 최종 카드 품질은 그대로(아주 맞음 72%, 틀린 카드 0.36), 1차 Haiku 호출(1~2.4초) 없음, 비용 −8%, 느린 10% 11.4 → 9.7초([넣은 것과 뺀 것](reports/2026-10-26-ml-first-call-decisions.md) 3-5 ①).

## 9. 한 줄로

> 고정된 한국어 문장 임베딩(KURE-v1, int8) 위에, LLM이 라벨을 단 합성 데이터로 학습한 은닉층 1개짜리 MLP 분류 머리 13개(다중 라벨 7, 다중 클래스 6). 판정 문턱은 dev 셋에서 F1과 오분류 비용으로 정했고, 로지스틱 회귀(linear probe)를 기준선으로 비교했다. 클래스 불균형을 고르게 맞춰 길 나누기 58.5 → 94.5%.
