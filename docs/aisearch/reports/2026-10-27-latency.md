# AI 책 찾기 첫 글 시간 줄이기 (2026-10-27)

> **이 문서가 답하는 것**: 질문을 보낸 뒤 화면에 첫 글이 보이기까지의 시간이 어느 단계에 쓰이는지(1절), Haiku 첫 토큰을 무엇이 정하는지(2절), 고친 세 가지(3절: 1안 이른 낱말 검색, 2안 표지·요약을 Haiku와 같이 읽기, 4안 되묻기 형식을 짧은·이어지는 질문에만), 로컬·운영 전후 숫자(4·6절), 하지 않은 것(5절).
>
> **답하지 않는 것**: 지금 각 단계가 어떤 표·칸을 읽고 무엇을 계산하는지 → [1-how-it-works](../1-how-it-works.md) 4-1절(이른 낱말 검색), 4-10절(카드 재료), 4-11절(2차 호출), 7절(로그 한 줄). 시험에 쓴 80문항과 품질 채점 방법 → [규칙 점검 4절](2026-10-27-rules.md). 버전마다 바뀐 것 → [2-versions.md](../2-versions.md).
>
> **그때 운영 버전**: v1.18.0(1·6절의 「전」). 고친 판이 [v1.19.0](../2-versions.md#v1190)(2026-10-28 00:00, `b356c995`)으로 나갔고, 지금 운영입니다.
>
> **지금(v1.19.0)과 다른 점**: 없음(이 문서의 「고친 판」이 지금 운영). 그 뒤 잰 것: plan 26 세션 요청으로 낱말 검색 질의 하나만 따로 잼 — 캐시가 빈 DB에서 질문 24개 중간값 106ms, 이미 읽은 뒤 16.1ms([plan-feedback 「사이클 26 질의 속도」](../../plan-feedback.md)). 남은 일 두 가지(형식 강제 빼기 전에 JSON 깨지는 비율 재기, 6절 「서버 첫 토큰 → 사용자 첫 글」 약 0.5초 나눠 재기)는 아직 하지 않았습니다.
>
> **이 문서의 이름**: 「첫 글」 = 사용자 쪽(시험 도구)이 SSE에서 첫 머리말 조각·카드·되묻기를 받은 때(요청부터). 「Haiku 첫 토큰」 = 서버 로그 `steps`의 `cards`(Haiku 호출 시작) → `llm-first`(첫 글 조각을 받음). 「v1.18.0」·「고친 판」은 4절에서 `t-base`·`t-fast`라는 이름으로 돌림. 1·2·4안의 번호는 사용자에게 낸 안 번호입니다. 3안은 형식 강제(structured output) 빼기로, 하지 않았습니다(5절, [plan-feedback](../../plan-feedback.md) 「첫 글 시간 줄이기」 줄).

AI 책 찾기는 답을 SSE로 흘려 보내므로, 사용자가 기다리는 시간은 **답이 다 끝나는 시간이 아니라 첫 글이 보이는 시간**입니다. 이 문서는 그 시간을 단계별로 쪼개 재고, 무엇을 고쳤고 무엇을 고치지 않았는지 숫자로 남깁니다.

- 브랜치 `claude/aisearch-faster-first`. 코드는 `AiSearchFlow`(`backend/.../aisearch/internal/flow/`), `MlFirstCall.firstKeywords`.
- 원본 숫자는 [`ai-search-eval/latency-*.json`](../../reports/ai-search-eval/)에 있고, 다시 돌리는 도구는 [`scripts/aisearch/eval/`](../../../scripts/aisearch/eval/)의 `ttft_probe.py`, `ttft_probe2.py`, `rules_run.py`, `timing_compare.py`입니다.

## 1. 지금 시간이 어디에 쓰이나 (운영 v1.18.0)

서버는 검색마다 로그 한 줄에 각 단계가 끝난 시각(요청 시작부터 ms)을 남깁니다(`steps encode=… ml=… nearest=… neighbours=… keyword=… vector=… mix=… cards=… llm-first=… llm-done=…`). 아래는 운영에서 검색 8번을 보낸 값입니다(이 8번의 원본 파일은 저장소에 없음).

| 단계 | 하는 일 | 중간값 | 느린 10% |
|---|---|---|---|
| encode | 질문 벡터 (임베딩 서버) | 146ms | 283ms |
| ml | 1차 신경망 (길·칸·관계) | 12ms | 15ms |
| nearest | 벡터로 가까운 책 | 97ms | 137ms |
| keyword | 낱말 검색 (pg_bigm LIKE) | 176ms | 294ms |
| cards | 후보 30권의 한 줄·연도·표지·AI 요약 읽기 (DB 4번) | 104ms | 142ms |
| Haiku 첫 토큰 | 프롬프트를 보내고 첫 조각이 오기까지 | 1,336ms | 1,667ms |
| **요청 → Haiku 첫 토큰** | | **약 1.91초** | |

- 운영 서버 → api.anthropic.com 망: TLS 약 16~35ms, 첫 바이트 약 20~40ms → 망은 원인이 아님.
- **Haiku 앞의 준비가 약 0.57초**이고, 그중 낱말 검색과 카드 읽기는 앞 단계를 기다릴 이유가 없는 일이었음.

## 2. Haiku 첫 토큰은 무엇이 정하나 (따로 잰 탐색)

실제 2차 지시문과 로컬 후보 30권으로 Haiku만 직접 불러, 형태를 하나씩 바꿔 가며 첫 토큰과 첫 문장(head) 첫 글자 시간을 쟀습니다(질문 3개 × 5번, 생각 끔, effort low). 원본: [`latency-ttft-probe-2026-10-27.json`](../../reports/ai-search-eval/latency-ttft-probe-2026-10-27.json), [`latency-ttft-probe2-2026-10-27.json`](../../reports/ai-search-eval/latency-ttft-probe2-2026-10-27.json).

| 바꾼 것 | 입력 토큰 | 첫 토큰 | head 첫 글자 (중간값) | head 느린 10% |
|---|---|---|---|---|
| A 그대로 (되묻기 지시문·형식) | 8,442 | 1.10초 | 1.24초 | 1.92초 |
| B 되묻기 없는 지시문·형식 | 7,573 | 1.19초 | 1.19초 | 1.29초 |
| C 한 줄을 80자까지 | 7,482 | 1.11초 | 1.25초 | 1.64초 |
| D 후보 20권 | 6,676 | 1.33초 | 1.49초 | 1.67초 |
| E 항목 표시·연도 빼기 | 7,722 | 1.11초 | 1.24초 | 1.70초 |
| F 프롬프트 캐싱 끔 | 8,442 | 1.09초 | 1.27초 | 1.60초 |

| 바꾼 것 (첫 토큰만) | 중간값 | 느린 10% |
|---|---|---|
| A 그대로 (형식 강제 + effort low) | 1.09초 | 1.22초 |
| G 형식 강제 없이 지시문으로 JSON | 0.86초 | 1.38초 |
| H effort 칸 없음 | 1.04초 | 1.18초 |
| T 아주 짧은 프롬프트 (바닥값) | 0.77초 | 0.81초 |
| U 아주 짧은 프롬프트 + 형식 강제 | 1.15초 | 2.21초 |

**읽은 것**

- 바닥값이 약 **0.77초**: 프롬프트를 아무리 줄여도 이 아래로는 안 내려감.
- **입력 크기와 캐싱은 첫 토큰을 거의 바꾸지 않음**(C·D·F). 후보를 20권으로 줄이면 오히려 느렸고 품질만 잃음 → 프롬프트 줄이기는 하지 않음.
- **형식 강제(structured output)가 약 0.25~0.4초**를 더함(T → U, A → G). 다만 강제를 빼면 JSON이 깨질 수 있어, 깨지는 비율을 재기 전에는 넣지 않음(아래 5절).
- **되묻기 칸이 head를 늦춤**: 되묻기 형식은 답이 `{"ask":{"question":"","choices":[]},`로 시작해서, 되묻지 않을 때도 이 빈 칸을 다 쓴 뒤에야 head가 나옴(A 1.24초 vs B 1.19초, 느린 10%는 1.92초 vs 1.29초).

## 3. 고친 것 세 가지

| | 문제 | 고친 방법 |
|---|---|---|
| 1안 | 낱말 검색이 질문 벡터 → 1차 신경망 → 가까운 책 → 이웃이 다 끝난 뒤에야 시작 | 첫 질문의 낱말은 질문만으로 정해지므로(`MlFirstCall.firstKeywords`), 질문 벡터를 만들 때 **낱말 검색을 같이 시작**(가상 스레드). 계획의 낱말이 같고 뺄 책이 없을 때만 그 결과를 쓰고(코드에서는 여기에 「벡터 후보와 RRF로 합칠 때」, 「핵심어가 없을 때」도 붙음, [1-how-it-works 4-1절](../1-how-it-works.md#4-1-이른-낱말-검색-첫-질문만)), 아니면 전처럼 다시 찾음 → **후보는 전과 같음** |
| 2안 | 표지·AI 요약을 다 읽은 뒤에 Haiku를 부름. 둘은 카드에만 쓰고 Haiku에게는 안 감 | 한 줄·연도만 읽고 **Haiku를 바로 부르고**, 표지·요약은 그동안 읽음. 첫 카드가 나갈 때 기다림(대개 이미 끝나 있음). 읽기가 실패하면 표지·요약 없이 카드만 |
| 4안 | 되묻기를 켜면 모든 질문에 되묻기 칸이 head 앞에 붙음 | 되묻기 형식은 **4낱말 이하 첫 질문과 이어지는 질문에만**. 5낱말 이상 첫 질문은 되묻기 없는 형식으로 바로 head부터. 4는 80문항 규칙 시험에서 되물은 가장 긴 질문(「요즘 읽을 만한 거」)의 낱말 수 |
