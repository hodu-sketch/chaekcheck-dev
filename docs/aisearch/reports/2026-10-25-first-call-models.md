# 1차 AI 호출을 작은 모델로 바꿀 수 있나: TF-IDF · KURE+분류기 · Cross-Encoder · Haiku (2026-10-25)

> **이 문서가 답하는 것**: 2026-10-25~27에 「1차 Haiku 호출이 하는 일(길 나누기 · 칸 고르기 · 검색어 만들기)을 LLM 없이 KURE 질문 벡터 + 작은 분류기로 할 수 있나」를 잰 실험 — 무엇을 왜 쟀나, 무엇으로 쟀나(질문 묶음 · 채점 · 지표), 결과 표, 그때 판단, 원본 파일.
>
> **답하지 않는 것**
> - 결정만 모은 표, 이 뒤의 실험(길 나누기 학습량, 이어 묻는 질문, 5갈래, 관계 분류기, v1.16.1~v1.16.3 고침) → [넣은 것과 뺀 것](2026-10-26-ml-first-call-decisions.md)
> - 지금 운영에서 1차 ML이 하는 계산(행렬곱 · 문턱 · 낱말 자르기) → [1-how-it-works.md 4-3절](../1-how-it-works.md)
> - 운영 모델의 구조와 학습 설명 → [3-ml-models.md](../3-ml-models.md)
>
> **그때 운영 버전**: v1.15.x. 1차 = Haiku(`Prompts.KEYWORD_SYSTEM`, 답 JSON = 책 찾기 아님 · 제목 같음 · 앞 책 가리킴 · 검색어 8개까지 · 핵심어 `core`). 후보 = 낱말 후보 50위와 질문 벡터 후보 60위를 RRF(점수 = Σ 1/(60 + 순위))로 한 줄로 세워 앞 30권, 대상 27,227권. 칸(분야 등)은 쓰지 않음.
>
> **지금과 다른 점**: 이 보고서의 「1차 Haiku를 통째로 바꾸는 것은 지금은 손해」(5절) 판단은 뒤에 바뀌었습니다. [v1.16.0](../2-versions.md#v1160)부터 운영 1차는 **KURE 벡터 위의 5갈래 MLP + 칸 MLP 11개**(첫 질문 · 이어 묻는 질문 모두)이고, [v1.16.1](../2-versions.md#v1161)부터 이어 묻는 질문은 관계 분류기(`FOLLOW_UP=relation`)가 나눕니다. Haiku 1차는 `CHAEKCHECK_AISEARCH_FIRST_CALL=haiku`이거나, 모델 파일이 없거나, 질문 벡터가 늦거나 실패한 검색에서만 씁니다. 운영 모델 파일은 이 보고서의 모델이 아니라 그 뒤에 다시 학습한 것입니다(0절 「운영과의 관계」). 모든 전후 숫자를 모은 표는 [모음](../4-portfolio.md).

책첵 AI 책 찾기의 1차 호출(Haiku)은 질문을 읽고 검색 조건을 JSON으로 돌려줍니다. 이 중 **「정해진 칸에서 고르는」 부분을 LLM 없이 작은 모델로 할 수 있는지**, 같은 시험 질문으로 재 봤습니다. 이 실험 때 운영 코드는 바꾸지 않았습니다(뒤에 v1.16.0으로 바꿈, 위 상자).

## 0. 이름표: 이 문서에 나오는 방식 이름

같은 글자가 다른 문서에서 다른 것을 가리킵니다. 특히 **「H」는 세 가지**입니다: 이 문서 5-4절의 H(Haiku 검색어 + Haiku 칸), [넣은 것과 뺀 것 3-2](2026-10-26-ml-first-call-decisions.md)의 H(그때 운영 Haiku 1차 + 앞 대화), [eval 보고서](2026-10-25-eval.md)의 H(낱말 + 벡터 RRF 후보 30권). 「P」도 [개선 보고서](2026-10-25-improvement.md)의 P와 같은 뜻(그때 운영 후보 만들기)이지만, 거기의 PF·PFx는 칸을 Sonnet이 단 것이고 여기 5-4절의 칸은 Haiku·MLP·LR이 단 것입니다.

**칸 고르기 방식 (3~5-3절)**

| 이름 | 입력 | 고르는 모델 | 칸을 고르는 규칙 | 운영과의 관계 |
|---|---|---|---|---|
| 늘 같은 답 | 없음 | 없음 | 학습 질문에서 가장 흔한 값을 늘 냄. 여러 개 고르는 칸(분야 등)은 빈 답이라 F1 0 | 기준선 |
| TF-IDF + 로지스틱 회귀 | 질문을 **글자 2~4개 조각**으로 자른 TF-IDF(`TfidfVectorizer(analyzer='char_wb', ngram_range=(2,4), min_df=2, sublinear_tf=True)`, 조각표는 학습 질문으로 만듦) | 칸마다 로지스틱 회귀(`C=4`) | 하나 고르는 칸: 확률이 가장 높은 값. 여러 개 고르는 칸: 값마다 확률 **0.35 이상**이면 고름(학습 질문에 2번 이상 나온 값만) | 쓰지 않음 |
| KURE + 로지스틱 회귀 (첫 판) | KURE-v1(원래 float32 모델) 질문 벡터 1,024개, 길이 1 | 같음 | 같음(0.35) | 쓰지 않음. 3-ml-models의 「linear probe」 기준선 |
| … + 칸마다 문턱 (5-1) | 같음 | 같음 | 0.35 대신 칸 종류마다 0.05~0.70에서 검증 질문(24묶음 100개)의 F1이 가장 높은 문턱 | 문턱 고르는 법은 운영 칸 머리와 같음 |
| 작은 신경망(MLP) | 같음 | 1024 → 512(ReLU, 드롭아웃 0.3) → 칸, 칸마다 sigmoid, 손실 BCE, AdamW(lr 1e-3, weight decay 1e-4), 배치 64, 60에포크 | 칸마다 문턱(위와 같은 방법) | **운영 칸 머리와 같은 뼈대.** 운영 파일은 학습 질문 6,298개로 다시 학습한 것([3-ml-models 3절](../3-ml-models.md)) |
| Haiku (칸 비교) | 질문 글 | Claude Haiku, 지시문 [`qlabel-RULES.md`](../../../scripts/aisearch/eval/qlabel-RULES.md) | Haiku가 JSON으로 칸을 닮 | 그때(v1.15) 운영 1차 Haiku는 이 칸을 내지 않음 → 「Haiku에게 이 칸을 시키면」의 숫자 |
| Cross-Encoder | 「질문」과 「"○○ 분야의 책"」 쌍 | bge-reranker-v2-m3, 학습 없음 | 쌍 점수가 칸 종류마다 고른 문턱 이상 | 쓰지 않음(4·4-1절) |

**전체 흐름 안 (5-4절)**: 1차만 바꾸고 나머지(후보 → 2차 Haiku → Sonnet 채점)는 같게 둠. 후보는 모두 「이름 댄 책의 이웃 먼저 → 낱말 50위 + 벡터 60위 RRF(k=60) → 같은 제목 하나만 → 30권」(`cands_more.py`의 P). 칸이 있는 안은 여기에 PFx를 더함: RRF 점수에 「질문 칸과 책 프로필 칸이 같은 칸 수 × 0.004」를 더해 다시 줄 세우고, 질문이 「소설 아님」인데 소설인 책과 빼 달라는 칸의 책은 맨 뒤로(`cands_facet.build_f`, 책 프로필은 27,227권 상세 사전 프로필).

| 안 | 검색어(낱말 후보에 쓰는 낱말) | 칸 (PFx에 쓰는 것) | 1차에 LLM | 운영과의 관계 |
|---|---|---|---|---|
| P | Haiku 1차의 검색어 + 핵심어(`kw-base`, 그때 운영 지시문) | 없음(PFx 안 함) | 씀 | **그때 운영 v1.15.x 재현** |
| H | P와 같음 | Haiku가 단 칸(`qlabel/haiku-E1`) | 씀 | 내지 않음 |
| HM | P와 같음 | MLP 칸(`facets-mlp.json`) | 씀 | 내지 않음 |
| M | **질문 낱말 그대로**: 빈칸·문장부호에서 자르고, 끝 조사 하나 떼고, 「책·추천·알려줘」 같은 말과 2글자 미만을 버린 앞 8개. 핵심어 없음 | MLP 칸 | **안 씀** | **v1.16.0 운영 1차의 모양**(운영 `QuestionWords`와 같은 규칙, [1-how-it-works 4-3 (라)](../1-how-it-works.md)) |
| L | M과 같음 | 로지스틱 회귀 칸(`facets-lr.json`) | 안 씀 | 내지 않음 |
| MT | 질문 낱말 앞 4개 + 책 프로필 주제어(Haiku가 27,227권에 단 주제어 중 2권 이상에 쓰인 약 10,400개, 미리 KURE 벡터로 만듦) 가운데 질문 벡터와 내적이 큰 4개 | MLP 칸 | 안 씀 | 내지 않음 |

H·HM·M·L·MT의 MLP·LR 칸은 학습 질문 6,298개 전부로 학습하고 칸마다 문턱(24묶음)을 고른 모델이 평가 질문 57개에 단 것(`predict_eval.py`).

**길 나누기 방식 (5-5·5-6절)**

| 이름 | 무엇 | 운영과의 관계 |
|---|---|---|
| Haiku (길 나누기) | 그때 운영 1차 지시문 `KEYWORD_SYSTEM` 그대로, 앞 대화 없이 한 줄씩(`route-HAIKU_RULES.md`). 답의 `notBook`·`titleLike`·`refersToShown`로 길을 정함 | 그때(v1.15) 운영 1차 |
| MLP v1 · LR v1 (5-5) | 칸 학습 질문 6,298개의 예/아니오 칸 셋(`notBook`·`titleLike`·`refersToShown`)을 따로 학습한 분류기 셋. 이 순서로 처음 「예」(확률 0.5 이상)인 길, 없으면 보통 질문(`route_clf.py`) | 쓰지 않음. 백업 `chaekcheck-data/ml/aisearch-classifier/v1-2026-10-26/` |
| MLP v2 · LR v2 (5-6) | 4갈래 분류기 하나(책 찾기 아님 / 제목만 / 앞 책 가리킴 / 보통 질문), MLP는 1024 → 512 → 4 softmax. 학습 = 6,298개 + 길 나누기 학습 질문 1,600개. 「보통 질문 아님」은 확률이 tau 이상일 때만(`route_v2.py`) | 쓰지 않음(v1.16.0 운영 파일은 이것에 「책첵 질문」을 더한 5갈래, [넣은 것과 뺀 것 3-3](2026-10-26-ml-first-call-decisions.md)). 백업 `…/v2-2026-10-26/` |
| + 제목 확인 | 「제목만」으로 본 질문이 운영 `TitleMatch.close`처럼 우리 책 제목·저자와 맞을 때만 「제목만」으로 둠 | 내지 않음 |

이름 「v1·v2」는 이 분류기 판 번호입니다. 되묻기 v1·v2(v1.17.0·v1.18.0)와 상관없습니다.

|---|---|---|

## 1-1. 말 정리 (이 실험의 구조)

```
질문 ─[KURE: 이미 만들어진 모델, 학습시키지 않음]→ 숫자 1,024개
     ─[고르는 부분: 우리가 학습시킴. 로지스틱 회귀 또는 작은 신경망]→ 칸마다 확률
     ─[문턱: 첫 판은 0.35 이상이면 고름, 5-1절부터 칸마다 고른 값]→ 답(소설 · 추리·스릴러 · 일본 …)
```

| 말 | 뜻 |
|---|---|
| KURE | 질문을 뜻이 담긴 숫자 1,024개로 바꾸는 한국어 모델. 운영 벡터 검색에 쓰는 것과 같음(운영은 int8로 줄인 판, 이 실험은 원래 float32 판). 이 실험에서는 고정 |
| TF-IDF | KURE 대신 쓰는 다른 입력: 질문을 글자 2~4개 조각으로 잘라 「어느 조각이 몇 번 나왔나」에 「드문 조각일수록 큰 무게」를 곱한 숫자. 학습 없이 계산 |
| 로지스틱 회귀 | 고르는 부분 후보 ①. 고정된 임베딩 위에 선형 분류기를 얹는 것을 **선형 프로브(linear probe)**라고 부름. 칸마다 「숫자 1,024개 × 가중치」를 한 번 더해 확률로. 하나하나의 영향만 더함 |
| 작은 신경망 (MLP) | 고르는 부분 후보 ②. 전문 용어로 **다층 퍼셉트론(MLP, Multi-Layer Perceptron)**: 은닉층(hidden layer) 1개·512칸, 활성화 함수 ReLU, 드롭아웃 0.3, 출력은 칸마다 시그모이드(여러 칸을 고르는 multi-label), 손실 함수 BCE(이진 교차 엔트로피), 최적화 AdamW, 60에포크. 숫자 1,024개 → 중간 특징 512개 → 칸 점수. 중간 단계 덕분에 영향들의 조합까지 배움. 모양은 로지스틱 회귀 앞에 한 단계를 끼운 것이지만, 두 단계를 처음부터 함께 학습 |
| 동결 인코더 + 분류 헤드 | KURE(인코더)는 고치지 않고(frozen) 위의 분류 부분(head)만 학습하는 방식. KURE까지 고치면 **미세 조정(fine-tuning)** |
| 학습 | 정답이 달린 학습 질문을 보며 가중치를 맞춰 가는 것. 학습량이 다른 모델은 각각 백지에서 따로 학습(이어서 학습한 것이 아님) |
| 문턱 | 확률이 몇 이상이면 그 칸을 고를지. 칸마다 검증 질문 100개로 고름 |
| 학습 / 검증 / 시험 질문 | 학습 = 가중치를 정함, 검증(24묶음 100개) = 문턱을 고름, 시험(25~30묶음 600개) = 점수만 매김. 시험 질문은 학습·문턱 고르기 어디에도 안 씀 |
| F1 | 여러 칸을 고르는 문제의 점수. 「고른 칸 중 맞은 비율」과 「맞혀야 할 칸 중 고른 비율」을 함께 본 값(0~100%). 이 문서는 모든 질문의 고른 칸을 합쳐 한 번에 셈(micro F1: 2·맞게 고른 수 / (2·맞게 고른 수 + 잘못 고른 수 + 놓친 수)) |
| 맞은 비율(정확도) | 예/아니오 칸과 하나 고르는 칸(대상·수준)의 점수: 답이 Sonnet 답과 같은 질문의 비율 |

| | 로지스틱 회귀 | 작은 신경망 |
|---|---|---|
| 계산 단계 | 1 | 2 |
| 배우는 가중치 (작은 칸 99개 기준) | 약 10만 | 약 57만 |
| 데이터가 늘 때 | 3,000개쯤에서 한계 | 더 오름 |
| 크기 · 속도 | 약 0.4MB · 1ms 안쪽 | 약 2MB · 1ms 안쪽 |

처음 계획은 로지스틱 회귀만이었고, 작은 신경망은 첫 결과가 낮아 원인을 찾으며 더한 비교 대상(5-1절부터). 두 방식 모두 단계마다 같은 시험으로 잼.

## 2. 데이터와 재는 법

- **질문 3,000개를 Sonnet이 만들고 정답 JSON을 닮** (하위 에이전트, API 키 없이). 씨앗을 먼저 만들어 12가지 유형(조건 하나·여럿, 빼 달라는 말, 부정어, 돌려 말하기, 부딪치는 조건, 막연한 질문, 「○○ 같은 책」, 책 찾기가 아닌 말, 제목만, 앞 책 가리키기)과 작은 칸 99개를 빠짐없이 나눠 담음. 사전 밖 값 0건. 도구: [`qgen_seeds.py`](../../../scripts/aisearch/eval/qgen_seeds.py), 지시문 [`qgen-RULES.md`](../../../scripts/aisearch/eval/qgen-RULES.md). 100개씩 한 묶음(`qgen/q-01.jsonl` ~ `q-30.jsonl`).

- **한 번씩 학습.** 3~5-2절 표는 시작값 하나로 한 번 학습한 값입니다. 5-3절의 MLP도 한 번씩입니다(시작값 3개 평균은 [넣은 것과 뺀 것 3-1](2026-10-26-ml-first-call-decisions.md)부터).
- 실제 사용자 질문은 저장하지 않으므로(ADR-0152) 쓰지 않음.

## 4-1. Cross-Encoder의 정확도 (2026-10-27에 채움)

처음에 「정확도만 재서 비교표에 넣겠다」고 했으나 속도만 재고 빠뜨렸음(사용자 2026-10-26 「크로스 인코더도 비교용으로 했었는데 어떻게 됐어?」로 알게 되어 채움). bge-reranker-v2-m3를 학습 없이 그대로: 칸마다 「질문 + "○○ 분야의 책"」 쌍의 점수를 내고, 문턱을 칸 종류마다 학습용 질문 100개(24묶음)로 골라 그 위면 고름. 채점은 다른 방식과 같은 micro F1.

| 칸 (F1) | Cross-Encoder (시험 200개 / 평가 57개) | TF-IDF | KURE + 로지스틱 | KURE + 작은 신경망 (5-1) | Haiku |
|---|---|---|---|---|---|
| 큰 칸 | 37.5% / 36.4% | 73.7% | 84.9% | **89.6%** | 93.4% |
| 작은 칸 | 43.5% / 27.9% | 38.2% | 48.6% | 78.2% | **87.6%** |
| 장르 | 22.9% / 32.6% | 28.6% | 25.5% | 61.8% | **82.8%** |
| 분위기 | 54.7% / 26.7% | 72.7% | 67.5% | 83.7% | **92.0%** |

- 다른 열은 시험 600개(25~30묶음), Cross-Encoder는 그중 25·26묶음 200개(속도 때문에 줄임)라 같은 질문은 아님. 같은 600개 안의 묶음이라 경향 비교로는 충분 [추론].
- 학습 없이 쓰면 **TF-IDF보다도 낮은 칸이 많음**(큰 칸 37 vs 74%). 쌍 하나의 「맞는 정도」 점수는 잘 내지만, 칸 이름을 문장 하나로 바꾼 것(「과학 분야의 책」)으로는 질문과 칸의 관계를 잘 못 잡음 [추론]. 문턱도 큰 칸 0.04처럼 낮게 잡혀 점수 분포가 칸마다 고르지 않음(고른 문턱: 큰 칸 0.04, 작은 칸 0.48, 장르 0.28, 분위기 0.82).
- 속도: 칸 146쌍(큰 칸·작은 칸·장르·분위기)에 질문 하나 **9.2초(PC 16스레드)**. 운영 서버(2코어)라면 몇 배 더 느림.
- 결론은 그대로: 정확도로도 속도로도 운영 후보가 아님. 미세조정하면 오를 수 있으나 쌍마다 돌리는 속도는 바뀌지 않음.
- 결과 파일: [`ai-search-eval/first-call/zeroshot-2026-10-27.json`](../../reports/ai-search-eval/first-call/zeroshot-2026-10-27.json), 도구 [`zeroshot.py`](../../../scripts/aisearch/eval/zeroshot.py)

## 5. 정리 (2026-10-25 첫 판단, 뒤 절에서 고친 곳 표시)

- **대신할 수 있는 것** (5-5절에서 일부 바로잡음: 예/아니오 칸은 대신할 수 없었음): 예/아니오 칸(책 찾기 아닌 말·제목만·앞 책 가리키기)과 「소설을 원하나」, 「빼 달라는 말이 있나」는 KURE + 분류기가 Haiku와 1~4%p 안. 1ms 안쪽, 추가 모델 없음.
- **아직 못 하는 것**: 첫 판에서는 작은 칸·장르·분위기에서 Haiku가 크게 앞섰으나(작은 칸 49% vs 88%), 문턱 조정과 작은 신경망으로 차이가 줄어듦(작은 칸 79% vs 88%, 큰 칸 90% vs 93%, 5-1절). 장르는 아직 66% vs 83%.
- **그래서** (5-4절 전 판단): 1차 Haiku를 통째로 바꾸는 것은 지금은 손해 — **5-4절의 전체 흐름 시험에서는 바꿔도 최종 카드가 같았음.** 다만 큰 칸·예/아니오를 분류기로 먼저 정해 두고 Haiku가 실패하거나 늦을 때 대신 쓰는 길(대체 경로)은 바로 쓸 수 있는 수준.
  - (2026-10-27 덧붙임) 운영은 반대로 갔음: v1.16.0부터 MLP가 1차를 맡고, Haiku가 되돌리기·대체 길(`FIRST_CALL=haiku`, 모델 파일이 없을 때, 질문 벡터가 늦거나 실패할 때). [넣은 것과 뺀 것](2026-10-26-ml-first-call-decisions.md) #9·#14.
- **Cross-Encoder**: 비교용으로만 잼(사용자 결정). 학습 없이는 큰 칸 F1 37%로 TF-IDF(74%)보다 낮고, 질문 하나 9초(4-1절) — 운영 후보가 아님.

## 5-1. 첫 판을 다듬으면 (같은 시험 600개)

첫 판은 모든 칸에 같은 문턱(확률 0.35 이상이면 그 칸을 고름)을 썼습니다. 학습용 질문 중 100개(24묶음)를 떼어 칸마다 문턱을 고르고, 작은 신경망(KURE 숫자 1,024개 → 512 → 칸)도 시험했습니다. 학습은 모두 2,306개.

| 칸 (F1) | 첫 판: KURE + 로지스틱 회귀, 문턱 0.35 | KURE + 로지스틱 회귀, 문턱을 칸마다 | KURE + 작은 신경망, 문턱을 칸마다 | Haiku |
|---|---|---|---|---|
| 큰 칸 | 84.9% | 85.5% | **89.6%** | 93.4% |
| 작은 칸 | 48.6% | **79.2%** | 78.2% | 87.6% |
| 장르 | 25.5% | **65.8%** | 61.8% | 82.8% |
| 분위기 | 67.5% | 80.4% | **83.7%** | 92.0% |

- 가장 큰 효과는 **문턱 조정**: 드문 칸은 확률이 낮게 나와 0.35를 못 넘었던 것. 작은 칸 48.6 → 79.2%.
- **학습 질문 수** (로지스틱 회귀, 첫 판 문턱 0.35, `improve.py` A): 500 → 1,000 → 1,500 → 2,306개에서 큰 칸 54 → 74 → 81 → 85%, 작은 칸 2 → 13 → 28 → 49%로 아직 오르는 중 → 질문을 더 만들면 더 오를 것 [추론]. (이 곡선의 결과 파일은 없음. 2,306개 값은 3절 표와 같음.)
- 시도했지만 효과 없음 (둘 다 로지스틱 회귀 위에서, `improve.py` B·C):
  - **책으로도 학습**: 책 27,227권(소개 KURE 벡터와 Haiku가 단 프로필 칸이 둘 다 있는 책)의 벡터를 입력, 프로필 칸을 정답으로 로지스틱 회귀를 따로 학습. 확률 = (1 − w) × 질문 모델 확률 + w × 책 모델 확률, w를 0 · 0.3 · 0.5 · 0.7 · 1.0 가운데 검증 질문으로 고르게 하니 **w = 0**(책 모델을 안 씀)이 뽑힘. 책 소개와 질문은 말투가 달라 책 쪽 비중을 올릴수록 나빠짐.
  - **큰 칸 아래에서만**: 작은 칸을 고른 큰 칸 아래 것만 남김 → 작은 칸 77.1%로 조금 나빠짐(같은 로지스틱 회귀 · 칸마다 문턱의 79.2%보다).
- 드는 것: 작은 신경망은 칸당 학습 2~3분(PC), 예측은 1ms 안쪽, 크기 약 2MB.
- (2026-10-29 덧붙임, 원본 대조) 로지스틱 회귀 두 열은 `steps.json`의 2,306개 값과 같습니다. 작은 신경망 열(89.6 / 78.2 / 61.8 / 83.7%)은 `mlp.py`가 화면에 낸 값으로 결과 파일이 없습니다. 같은 방법으로 5-3절에서 다시 학습한 값은 89.5 / 78.5 / 61.5 / 83.7%(`mlp-steps.json`)로, 시작값에 따른 차이입니다.

## 5-2. 약한 칸을 노린 질문 3,000개를 더 넣으면 (같은 시험 600개)

칸별 학습 수와 시험 점수([`weak.json`](../../reports/ai-search-eval/first-call/weak.json))로 약한 칸을 찾아(장르는 칸당 학습 질문 13개쯤, 작은 칸 18개쯤) 씨앗을 다시 짬: 장르 14개 × 약 80개, 작은 칸은 학습 수가 적고 점수가 낮을수록 많이, 나머지는 분위기·형식. Sonnet이 3,000개를 더 씀(31~60묶음, 씨앗 `qgen_seeds2.py`: 장르마다 약 80개, 작은 칸마다 15개 이상). 시험 질문 600개는 그대로.

**학습량에 따른 점수** (KURE + 로지스틱 회귀, 칸마다 문턱, F1, [`steps.json`](../../reports/ai-search-eval/first-call/steps.json)):

| 학습 질문 | 큰 칸 | 작은 칸 | 장르 | 분위기 |
|---|---|---|---|---|
| 2,306 | 85.5% | 79.2% | 65.8% | 80.4% |
| 3,306 (+1,000) | 86.1% | 80.4% | 67.3% | 81.1% |
| 4,306 (+2,000) | 86.5% | 80.6% | 67.4% | 82.1% |
| 5,300 (+2,994) | 85.9% | 80.9% | 66.7% | 82.4% |

→ 1,000개씩 더해도 +0~1.5%p라 **거의 평평함**. 로지스틱 회귀는 질문 2,000~3,000개에서 거의 다 배움. 그래서 더 늘리지 않음(사용자 기준: 선형으로 오르면 6,000개까지).

**작은 신경망으로 5,300개를 학습하면** (KURE + MLP, 칸마다 문턱, F1, `retrain2.py`):

| 칸 | 2,306개 신경망 (5-1) | 5,300개 신경망 | Haiku |
|---|---|---|---|
| 큰 칸 | 89.6% | **90.7%** | 93.4% |
| 작은 칸 | 78.2% | **85.0%** | 87.6% |
| 장르 | 61.8% | **71.6%** | 82.8% |
| 분위기 | 83.7% | **88.4%** | 92.0% |

→ 로지스틱 회귀는 평평했지만 **신경망은 데이터가 늘수록 더 배움**: 작은 칸 +6.8, 장르 +9.8, 분위기 +4.7%p. Haiku와의 차이가 큰 칸 2.7, 작은 칸 2.6, 분위기 3.6%p로 좁혀짐. 장르만 11%p 차이가 남음. (큰 칸·작은 칸·장르는 60묶음 전 5,200개, 분위기는 5,300개로 학습.)

- (2026-10-29 덧붙임, 원본 대조) 이 표의 신경망 값도 결과 파일이 없습니다(`retrain2.py` 화면 출력). 5-3절에서 같은 5,300개로 다시 학습한 값은 91.0 / 83.9 / 71.7 / 88.5%입니다. [3-ml-models 7절](../3-ml-models.md)의 「약한 칸 질문 3,000개 더함」 줄은 이 표의 값입니다.

**드는 것**: 질문 3,000개 = Sonnet 하위 에이전트 30묶음(묶음마다 약 10만 토큰, 2.5~3분). 신경망 학습은 칸마다 PC에서 수 분, 예측은 1ms 안쪽.

## 5-3. 학습량 × 방식 (같은 시험 600개, F1)

약한 칸 질문을 1,000개 더 만들어(61~70묶음, Sonnet, `qgen_seeds3.py`) 1,000개 단위로 두 방식을 같은 방법으로 잼: 학습량마다 백지에서 따로 학습 → 검증 100개로 문턱 → 시험 600개. 결과 파일: 로지스틱 회귀 [`steps.json`](../../reports/ai-search-eval/first-call/steps.json), MLP [`mlp-steps.json`](../../reports/ai-search-eval/first-call/mlp-steps.json). 둘 다 시작값 하나로 한 번씩.

| 학습 질문 | 큰 칸 LR / MLP | 작은 칸 LR / MLP | 장르 LR / MLP | 분위기 LR / MLP |
|---|---|---|---|---|
| 2,306 | 85.5 / 89.5 | 79.2 / 78.5 | 65.8 / 61.5 | 80.4 / 83.7 |
| 3,306 | 86.1 / 90.6 | 80.4 / 82.6 | 67.3 / 67.3 | 81.1 / 86.2 |
| 4,306 | 86.5 / **91.0** | 80.6 / 84.2 | 67.4 / 68.9 | 82.1 / 86.8 |
| 5,300 | 85.9 / **91.0** | 80.9 / 83.9 | 66.7 / **71.7** | 82.4 / **88.5** |
| 6,298 | 87.3 / 89.8 | 81.6 / **86.5** | 70.7 / 71.0 | 84.6 / 86.2 |
| (Haiku) | 93.4 | 87.6 | 82.8 | 92.0 |

LR = KURE + 로지스틱 회귀, MLP = KURE + 작은 신경망, 둘 다 칸마다 문턱. 같은 학습량에서 MLP가 대체로 2~6%p 높음(2,306개의 작은 칸·장르만 LR이 높음). **6,298개 MLP가 v1.16.0 운영 칸 머리의 학습량**입니다(운영 파일은 칸 머리 11개를 길 나누기 머리와 함께 내보낸 것: v1.16.0 `export_first_call.py`, v1.16.1부터 `export_first_call2.py`).

**읽는 법**
- MLP는 2,306 → 4,306개에서 크게 오르고(작은 칸 +5.7, 장르 +7.4%p) 그 뒤로는 ±1~2%p 안에서 오르내림 → **4,000~5,000개에서 거의 다 배움**. 작은 칸만 6,298개에서도 +2.6%p.
- LR은 6,298개에서 조금 오름(장르 +4%p) — 61~70묶음이 장르를 많이 담은 영향 [추론].
- 선형으로 오르지 않으므로 질문을 더 만들지 않음(사용자 기준).
- 최고 점수 기준 Haiku와의 차이: 큰 칸 2.4, 작은 칸 1.1, 분위기 3.5, 장르 11.1%p.

**드는 것**: 질문 4,000개 추가 = Sonnet 하위 에이전트 40묶음(묶음마다 약 10만 토큰). MLP 학습은 학습량마다 PC에서 1~3분, 예측 1ms 안쪽.

## 5-4. 전체 흐름에 넣어 최종 카드로 (질문 57개, 2차 Haiku까지, 같은 채점표)

**무엇을 왜**: 칸 점수(F1)가 Haiku보다 조금 낮아도, 최종 카드가 나빠지는지는 따로 재야 함. 1차 호출만 바꾸고 나머지(후보 → 2차 Haiku가 고름 → Sonnet 심사)는 같게 둠.

## 5-5. 길 나누기만 따로: 책 찾기 아님 · 제목만 · 앞 책 가리킴 (질문 400개)

**무엇으로**: Sonnet이 유형마다 100개(책 찾기 아님 · 제목·저자만 · 앞 책 가리킴 · **헷갈리는 보통 질문**: 「한강 소설 추천해줘」 「채식주의자 같은 책」 「심리학」 「도서관에서 빌리기 좋은 두꺼운 소설」). 400개를 한 목록에 넣고, 앞 대화 없이 한 줄씩 판단. 지시문: [`route-RULES.md`](../../../scripts/aisearch/eval/route-RULES.md). 점수 = 정답 길과 같은 질문의 비율(유형별, 전체). 「보통 질문을 막음」 = 보통 질문(헷갈리는 보통 질문 100개)을 「책 찾기 아님」으로 보내 검색이 안 되는 수. 방식은 0절 「길 나누기 방식」(Haiku · MLP v1 · LR v1). 결과 [`route-scores.json`](../../reports/ai-search-eval/first-call/route-scores.json), 도구 `route_clf.py`, `route_score.py`.

## 5-6. 길 나누기 전용 학습 질문 1,600개로 다시 학습 (같은 질문 400개, 2026-10-26)

5-5절의 원인(학습 질문에 세 유형이 1% 미만)을 고치려고, Sonnet이 **유형마다 400개씩 고르게** 길 나누기 학습 질문 1,600개를 새로 씀(책 찾기 아님 · 제목·저자만 · 앞 책 가리킴 · 헷갈리는 보통 질문). 시험 400개와 같은 글은 쓰지 않게 막음(`avoid.txt`). 지시문: [`route-TRAIN_RULES.md`](../../../scripts/aisearch/eval/route-TRAIN_RULES.md).

- **제목 확인은 빼는 게 나음**: 시험의 「제목만」 질문 상당수가 우리 2만 7천 권에 없는 책이라 확인을 통과 못 함(95% → 63%). 운영에서도 「제목만」은 검색을 막지 않고 「직접 찾기」 버튼만 더 띄우므로, 틀려도 손해가 작음.
- **MLP v2가 틀린 22개**(종류별):
  - 책 찾기 아님 → 보통 질문 5 (「사는게 왜이렇게 힘들지」 「요즘 너무 지치고 힘들다」 「치킨 시켜줘」 「Hello」 「나 내일 시험인데 떨려」): 검색은 돌지만 결과가 엉뚱할 뿐, 사용자가 막히지 않음.
  - 책 찾기 아님 → 제목만 4 (「하이」 「나 살쪘나봐」 「상호대차가 뭔가요?」 「영어로 번역해줘 감사합니다」), 보통 질문 → 제목만 5 (「자존감」 「고독」 「SF」 등 한 낱말): 검색은 그대로 돌므로 손해 작음.
  - 제목만 → 보통 질문 4 (「공정하다는 착각」 「거꾸로 읽는 세계사」 등 긴 제목): 검색이 그 책을 찾으면 손해 작음.
  - **손해가 큰 것**: 보통 질문을 「책 찾기 아님」으로 막음 2 (「독서 모임에서 같이 읽을 만한 책 골라줘」, 제목 「불편한 편의점」), 보통 질문 → 「앞 책 가리킴」 1 (「이문열 삼국지 말고 다른 삼국지」: 첫 질문이면 앞 책이 없어 운영은 보통 검색으로 돌아감).
- Haiku는 틀린 9개 중 6개가 앞 대화 없이 받은 「앞 책 가리킴」이라 운영(앞 대화 함께)에서는 더 높을 것 [추론]. 분류기는 앞 대화를 보지 않으므로, **첫 질문만 분류기, 이어 묻는 질문은 Haiku**로 나누는 것이 맞음. (2026-10-27 덧붙임: 뒤에 바뀜. 이어 묻는 질문도 v1.16.0부터 ML, v1.16.1부터 관계 분류기 — [결정 #18·#24](2026-10-26-ml-first-call-decisions.md).)
- **운영과의 관계**: MLP v2는 운영에 넣지 않았습니다. 이것에 학습량을 늘리고(3-1) 「책첵 질문」 갈래를 더한 5갈래(3-3, tau 0.30)가 v1.16.0 운영 파일, 짧은 장르 질문 300개를 더한 「라우터 B」(3-4, tau 0.55)가 v1.16.1부터 지금까지의 운영 파일입니다([넣은 것과 뺀 것 0절](2026-10-26-ml-first-call-decisions.md)).
- 비용: 4갈래 MLP 파일 약 2MB, 한 질문 1ms 안쪽(KURE 벡터는 검색에 이미 만듦).
