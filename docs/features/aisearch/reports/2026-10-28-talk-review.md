## 1. 요약

- **우리가 정한 문구로 모델 글을 가리는 곳**이 사용자에게 보이는 것만 6곳. 가장 어색한 둘: ① 모델이 「안녕하세요! 어떤 책을…」처럼 잘 답해도 고른 책이 0권이면 웹이 그 글을 지우고 「맞는 책을 찾지 못했어요. 다른 말로 써 보시겠어요?」로 바꿈(점검 57턴 중 **5턴**), ② 책 찾기가 아닌 말에는 모델을 부르지 않고 「어떤 책을 찾으세요? 이렇게 물어보셔도 돼요.」 + 무작위 예시 3개(**6턴**: 「오늘 날씨 어때」, 「너 누구야」, 「로그인 어떻게 해?」, 「잠이 안 와」, 「작가가 누구야?」, 「추천 별로야」).
- **마지막 정리 글은 지금 없음**: 답 JSON이 `head`(한 문장) + 책마다 글뿐. 스키마에 `tail`(상황별 정리)을 더하면 됨 — 첫 글 시간에는 영향 없음(카드 뒤에 씀).
- **대화 기억**: 웹이 앞 턴 **5개**만 보내고, 모델은 그 턴들의 **질문과 책 제목만** 봄(자기가 쓴 머리말·카드 글은 못 봄). 한 대화는 **20턴**에서 「새 대화를 시작해 주세요」. → 세션당 질문 수 N을 정해 N턴을 모두 기억하고, 앞 답의 머리말도 보내는 안.
- **책 밖 대화**: 지금은 세 길로 갈려 들쭉날쭉(고정 되묻기 / 한 낱말이면 그 말로 책 검색 → 「「고마워」와 관련해서 어떤 책을 찾으시나요?」 / 사이트 질문이면 사이트 안내). 1차 신경망이 「로그인 어떻게 해?」를 사이트 질문으로, 「잠이 안 와」를 책 질문으로, 「작가가 누구야?」를 앞 책 질문으로 알아보지 못함.
- 그 밖에 규칙 어김 3건(묻지 않은 「2026년 기준」, 「분량이 확인되는 책은 아니지만」, 앞 책을 묻는 답의 엉킨 머리말)과, 평가 세션이 찾은 「그거 말고」 다섯 가지.

## 2. 어떻게 봤나

- **코드 읽기**: 서버 `AiSearchFlow`·`Prompts`·`PickStreamParser`·`MlFirstCall`, 웹 `AiChatPage`·`aiSearchText`·`aiChatStore`에서 모델 글이 그대로 보이지 않는 곳, 기억, 책 밖 질문의 길을 줄 번호까지 찾음.
- **대화 점검**: 운영과 같은 설정의 로컬 서버(v1.19.0 코드, 1차 ML·관계 분류기·되묻기·생각 끔·캐시)에 일상 말·엉뚱한 말·이어 묻기를 섞은 **대화 37개(57턴)**를 한 번씩 보내고 화면에 보이는 그대로 기록(점수 채점은 하지 않고, 결과 종류와 문구를 셈). 질문 목록은 도구 안 `DIALOGS`. 도구 `scripts/aisearch/eval/talk_probe.py`, 원본 [`talk-probe-2026-10-28.md`](../eval-data/talk-probe-2026-10-28.md)(사람이 읽는 판)·`.json`.
- **평가 세션의 운영 화면 점검**(2026-10-27): 「AI 관련 기초 도서 → 사진 → 나도 잘 모르겠어 → 아 그거말고 → 아까전에 이야기한거잖아 → 아니아니 그거말고」.

결과 나눔(57턴): 카드 답 32 · 되묻기 17(그중 고정 되묻기 6) · 책 없음 5 · 사이트 안내 3.

## 3. 요청 ①: 모델 글을 손으로 바꾸지 않기

**사용자에게 보이는, 우리가 바꾸거나 가리는 곳**

| # | 언제 | 지금 하는 일 | 점검에서 | 고칠 안 |
|---|---|---|---|---|
| R1 | 모델이 책을 0권 고름(`no_match`) | 스트리밍으로 보이던 모델 머리말을 **끝나는 순간 지우고** 「맞는 책을 찾지 못했어요. 다른 말로 써 보시겠어요?」 + 무작위 예시 3개(웹 `AiChatPage` 407줄) | 5턴. 지워진 글 예: 「안녕하세요! 어떤 책을 찾으시는지 알려주시면 맞는 책을 골라 드릴게요.」, 「철학 책 중에서 쉬운 것을 찾으시는 거라면, 앞서 보여 드린 책들 가운데…」 | 모델 머리말을 그대로 둠. 고정 문구는 머리말이 비었을 때만. 예시 단추는 모델이 대화에 맞춰 내게(R2와 같은 길) |
| R2 | 1차가 「책 찾기 아님」으로 봄 | 모델을 부르지 않고 「어떤 책을 찾으세요? 이렇게 물어보셔도 돼요.」 + 10개 중 무작위 3개(`Prompts.NOT_BOOK_ASK`·`NOT_BOOK_CHOICES`) | 6턴. 대화와 상관없는 예시(「잠이 안 와」에 「처음 읽는 경제 교양서」) | 4절의 「대화 길」로 모델이 답하게 |
| R3 | 되묻기 힌트 | 모델이 이미 「원하는 게 따로 있으면 직접 적어 주세요」라고 쓰는데 웹이 「고르시면 그 답으로 이어서 찾아요. 직접 써서 물어도 돼요.」를 또 붙임 | 되묻기 17턴 중 11턴에 같은 뜻이 두 번 | 웹 힌트 빼기(또는 첫 문장만) |
| R4 | 카드 글 300자 | 300자에서 표시 없이 자름 | 규칙 시험 카드 2,106장(첫 글 시간 시험의 `t-base`·`t-fast` 두 판 × 두 번)·점검 223장 중 300자에 닿은 것 **0장**(가장 긴 136자) | 실제로는 안 일어남 → 문장 끝에서 자르게만 바꾸거나 그대로 |
| R5 | 되묻기를 쓰다 호출이 실패 | 되묻는 말을 버리고 글 없는 카드 8장 | 점검에선 없음 | 되묻는 말이 이미 나왔으면 그것을 보여 줌 |
| R6 | 사이트 답 | 모델 답을 한 번에(스트리밍 아님) + 「책첵이란? 자세히 보기 →」·「답은 … AI가 썼어요.」 | 3턴 | 스트리밍으로 바꾸면 첫 글이 빨라짐(지금 1.97~5.24초). 안내 줄은 유지 |

- 바꾸지 않아도 되는 것: 오류·한도 문구(「잠시 뒤에 다시 써 주세요」 등), 「책을 찾고 있어요」, 입력창 아래 「AI가 썼어요」 안내 — 모델 글을 대신하지 않음.
- 확인한 것: 웹은 모델 글을 글자 그대로 넣음(마크업 해석·글자 바꾸기 없음).

## 4. 요청 ②: 마지막에 상황별 정리

- **지금**: 스키마 `{"head", "picks":[{no, fit, text}]}`(되묻기 판은 앞에 `ask`). 카드 뒤에 오는 글이 없고, 서버는 `done`만 보냄.
- **안**: 스키마 끝에 `tail`을 더함 — 「고른 책들을 질문보다 더 자세한 상황으로 나눠 어느 책이 어디에 맞는지(예: 「출퇴근 30분에 한 편씩: 『찰나』, 『찬란한 타인들』 / 주말에 오래 생각하며: 『…』」), 나눌 상황이 없으면 한두 문장 총정리」. `tail` 조각을 새 SSE 이벤트(`tail-delta`)로 흘려 카드 아래에 보여 줌.
- **비용·시간**: 첫 글 시간은 그대로(카드 뒤에 씀). 답이 끝나는 시간과 출력 토큰은 늘어남 — 지금 출력 토큰 중간값 약 660 → 약 +150~250 예상 [추정], 출력 단가로 검색 1번에 약 +$0.0001. 고친 뒤 규칙 시험으로 잼(아래 7절).
- **주의**: 정리에도 지금 규칙(책 정보에 없는 말 지어내지 않기, 「후보」·「목록」 쓰지 않기)을 똑같이 걸어야 함. 책이 1~2권이면 정리를 빼거나 한 문장.

## 5. 요청 ③: 대화 기억과 세션당 질문 수

**지금**

| | 값 | 어디 |
|---|---|---|
| 보내는 앞 턴 | 마지막 **5개**(끝난 턴만) | 웹 `aiSearchText.ts` `HISTORY_SENT = 5`, 서버 `application.yml` `history-turns: 5`(넘으면 400) |
| 턴마다 모델이 보는 것 | 질문 + 「보여 준 책:」 제목들, 되묻기 턴은 「되물은 말 / 고를 답」 | `Prompts.pickMessages` |
| 모델이 못 보는 것 | 자기가 쓴 머리말·카드 글, 사이트 답, 책 없음 턴의 머리말 | 같음 |
| 1차(ML)가 보는 것 | 바로 앞 질문 하나(「둘」, 「합쳐」 같은 말이면 앞 질문 여럿을 이음) | `MlFirstCall`, `EarlierTopics` |
| 한 대화 | **20턴**에서 입력창 대신 「새 대화를 시작해 주세요」 | 웹 `AiChatPage` `full = chat.turns.length >= TURNS_MAX`(`aiSearchText.ts` `TURNS_MAX = 20`) |
| 저장 | 브라우저 탭 안(sessionStorage), 탭을 닫으면 사라짐 | `aiChatStore` |

- 그래서 6번째 앞 질문은 잊고(20턴까지 이어지는데 기억은 5턴), 자기가 무슨 말을 했는지 모름 → 「아까 말한 거」, 「두 번째 책 어때?」 같은 말에 어긋남. 점검에서 「두 번째 책 어때?」의 머리말이 「두 번째로 보여 드린 책은 히가시노 게이고의 『하우스메이드』가 아니라 『하우스메이드』가 맞고…」로 엉킴(그 책의 저자도 틀림).

**안**: 「세션당 질문 N개, N개를 모두 기억, 넘으면 새 세션」

- 웹·서버의 5와 20을 하나의 N으로(예: **N = 10** [안]). 입력창 위에 「이 대화 7/10」, N개를 넘으면 「새 대화」 단추(지금 20턴 화면과 같은 꼴).
- 앞 턴마다 모델에게 질문 + 보여 준 책 제목 **+ 자기가 쓴 머리말**(짧음)을 보냄. 카드 글까지 보내면 길어지므로 머리말만 [안].
- **토큰·시간**: 앞 턴 하나에 약 60~100 토큰(제목 8개 + 머리말) → 10턴이면 입력 +0.6~1k 토큰. 2026-10-27 측정에서 **입력 크기는 첫 토큰 시간을 거의 바꾸지 않았음**(입력 6,676~8,442 토큰에서 1.09~1.33초, [첫 글 시간 2절](2026-10-27-latency.md)). 입력 단가로 검색 1번에 +$0.0001 안쪽.
- 1차 관계 분류기는 지금처럼 바로 앞 질문과의 관계만 봄(학습이 그 꼴).

## 6. 요청 ④: 책 밖 대화는 부드럽게 책으로

**지금 세 길**

| 말 | 지금 | 점검 |
|---|---|---|
| 여러 낱말의 책 밖 말 | 고정 되묻기(R2), 0.3초 | 「오늘 날씨 어때」, 「너 누구야」, 「추천 별로야」 |
| 한 낱말(공백 없음, 글자 2개 이상) | 그 말로 책을 찾고 2차가 되물음 | 「안녕」 → 「어떤 종류의 책을 찾고 계신가요? …」(3.58초), 「고마워」 → 「「고마워」와 관련해서 어떤 책을 찾으시나요? 감사하는 마음을 다룬 자기계발서…」 |
| 1차가 사이트 질문으로 봄 | 사이트 지시문이 답함(인사·감사엔 짧게) | 「책첵이 뭐야」, 「전자책 빌리는 법」, 「왜 이렇게 못 찾아 진짜」(사과 + 지역 안내, 5.24초) |

**1차가 잘못 나눈 것**(1차 신경망 길 나누기): 「로그인 어떻게 해?」 → 책 찾기 아님(사이트 질문이어야), 「잠이 안 와」 → 책 찾기 아님(잠·불면 책 질문으로 볼 만함), 「작가가 누구야?」 → 책 찾기 아님(바로 앞 책을 묻는 말), 「책 말고 영화 추천해줘」 → 책 질문(영화 책을 되물음).

**안: 「대화 길」 하나로**

- 책 찾기 아님·인사·감사·불평·엉뚱한 말은 모두 짧은 모델 호출 하나(사이트 답과 같은 꼴, 해요체 1~2문장)로: 그 말에 먼저 자연스럽게 답하고 → 책 이야기로 부드럽게 이끌고 → **대화에 맞춘** 예시 2~3개(앞 대화가 있으면 그 주제에서). 예: 「고마워」 → 「도움이 됐다니 다행이에요. 비슷한 결의 에세이를 더 찾아 드릴까요?」 + 「비슷한 위로 에세이 더」.
- 책·사이트 밖 부탁(「영화 추천해줘」)은 「영화는 잘 모르지만, 영화로도 나온 소설이나 영화 이야기를 다룬 책은 찾아 드릴 수 있어요」처럼.
- 시간: 고정 되묻기 0.3초 → 모델 답 약 1.5~2초 [추정]. 대신 대화에 맞음.
- 1차 길 나누기에 「대화」 갈래를 더하거나(학습 질문 추가), 지금 「책 찾기 아님」을 이 길로 보냄. 위 잘못 나눈 4가지 같은 말을 학습 질문에 더해 다시 학습(5갈래 학습 때 갈래당 600개로 기존 시험 600개 94.6%. 이것은 v1.16.0 판이고, 짧은 질문 300개를 더한 지금 운영 판(라우터 B, v1.16.1~)은 93.9%, [ML 모델 설명](../3-ml-models.md)).
- 한 낱말 예외(「안녕」, 「고마워」가 책 검색으로 가는 것)는 인사·감사 낱말을 「대화 길」로.

## 7. 그 밖에 어색했던 것

| # | 말 | 보인 것 | 왜 어색한가 | 안 |
|---|---|---|---|---|
| E1 | 「요리 → 한식」 | 「2026년 기준으로 집에서 한식을 차리기 좋은 최근 책들을…」 | 묻지 않은 시기(지시문 P12 어김) | 지시문 예시 보강, 서버에서 「년 기준」 같은 말 걸러 재시험 |
| E2 | 「추리 소설 → 그 중에 제일 짧은 거」 | 「분량이 확인되는 책은 아니지만…」 + 추리 퀴즈 책 | 확인 못 한다는 말(P13 어김), 소설이 아닌 책 | 같음 + 앞 조건(소설) 이어 지키기 |
| E3 | 「추리 소설 → 두 번째 책 어때?」 | 엉킨 머리말, 틀린 저자 | 머리말 한 문장 제한 + 앞 답을 못 봄 | 5절(머리말 기억), 앞 책 한 권을 묻는 말(ask_one)엔 머리말 두세 문장 허용 |
| E4 | 「철학 → 쉬운 걸로 → 더 쉬운 거」 | 책 없음(R1로 고정 문구) | 앞에서 보인 쉬운 책도 다시 보여 줄 수 있어야 | 「더 ~한 거」는 앞 책도 후보로(지금 continue만 그렇게 함) |
| E5 | 「사진 → 나도 잘 모르겠어」 | 사진 입문 책 6권(이번 점검에선 괜찮음) | 평가 세션이 본 운영에선 또 되물음 | 되물은 직후 「모르겠어」엔 갈래마다 2~3권씩 섞어 보여 주기, 연달아 되묻기는 한 번까지 |
| E6 | 「아 그거말고」, 「아니아니 그거말고」 | 책 없음 3턴 | 대화를 가리키는 말인데 R1로 지워짐. 평가 세션이 본 운영에선 「말」이 검색어로 들어가 말하기 책 | 「그거」·「말고」·「아니」를 검색어에서 빼기, 되물음 뒤면 대화에 나온 주제로 버튼 되묻기 |
| E7 | 「아까전에 이야기한거잖아」 | 책 없음 | 앞 주제로 돌아가기인데 앞에서 보인 책을 빼서 남은 게 없음 | 앞 주제로 돌아가는 말은 앞 책도 다시 |
| E8 | 「해리포터」 | 비평서·원서 학습서·판타지를 되물음 | 대개 그 책 자체를 원함 | 제목처럼 보이는 말은 그 책을 먼저 보여 주고 비슷한 책을 덧붙임 |

- 평가 세션의 다섯 가지(E5~E7 + 「그거」 검색어 빼기 + 대화에서 버튼 만들기)는 관계 분류기·검색어 쪽과 겹치므로 이 계획에 함께 넣음.
