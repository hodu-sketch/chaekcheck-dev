# AI 책 찾기: 버전별로 무엇이 바뀌었나

AI 책 찾기(사이클 24)를 운영에 낸 순서대로 하나씩 적은 문서입니다. 비슷해 보이는 고침이 많아 헷갈리기 쉬워서, 버전마다 **바꾼 것 · 왜 · 숫자 · 그 뒤**를 따로 적습니다.

> **이 문서가 답하는 것**: 버전(v1.10.0~v1.22.3)과 코드 배포 없는 데이터 넣기마다 무엇을 바꿨나, 왜, 전→후 숫자, 그 뒤 어떻게 됐나. 재 보고 운영에 넣지 않은 안.
> **답하지 않는 것**: 지금(v1.19.0) 요청 하나가 도는 자세한 길 → [1-how-it-works.md](1-how-it-works.md) · ML 모델 학습 → [3-ml-models.md](3-ml-models.md) · 결과 모음 → [4-results.md](4-results.md) · 실험마다의 재는 방법과 원본 → [reports/](reports/) · 운영 명령 → [6-aisearch.md](../../maintenance/6-aisearch.md)

- 「바꾼 것」 줄 앞의 [대괄호]는 [1-how-it-works.md](1-how-it-works.md)의 절입니다: 2 요청, 3 데이터, 4 단계별(질문 벡터 4-2 / ML 1차 4-3 / 낱말 후보 4-7 / 벡터 후보 4-8 / 합치기 4-9 / 카드 재료 4-10 / 2차 호출 4-11 / SSE 4-12), 5 웹, 8 설정. 이 문서에서 「1차 ML」은 그 문서의 「ML 1차」와 같은 말입니다.
- 출처: [`CHANGELOG.md`](../../../CHANGELOG.md), git 태그와 커밋, 버전 사이 `git diff`(`backend/src/main/java/com/chaekcheck/aisearch`, `web/src/features/aisearch`, `deploy/prod/prod.env`), [4-results.md](4-results.md)와 각 보고서, [`maintenance/6-aisearch.md`](../../maintenance/6-aisearch.md), [`plan-feedback.md`](../../cycles/plan-feedback.md)(`# 사이클 24`, `# AI 검색 3만 권`, `# 보유 도서관 많은 10만 권`, `# 사이클 23 (이어서)`).

## 헷갈리기 쉬운 것

**되묻기 세 가지**

| | v1.17.0 되묻기 v1 | v1.18.0 되묻기 v2 | v1.19.0 되묻기 칸 범위 |
|---|---|---|---|
| 무엇 | 2차 JSON 맨 앞에 `ask` 칸을 둠. 뜻이 갈리면 책 대신 되묻는 말 + 버튼 | v1 위에 넷: 2낱말 이하 질문에 「후보 분야」 줄, 「직접 적어 달라」는 말, 직접 쓴 답을 앞 질문과 이어 찾기, 8권까지 채우기 | `ask` 칸이 든 형식을 **4낱말 이하 첫 질문과 이어지는 질문에만** 씀 |
| 왜 | 에이전트 시험에서 쓸모 있던 것이 되묻기뿐 | 「사진」에 안 되물음, 버튼 대신 쓴 「인상주의」가 「그림」과 안 이어짐 | 되묻지 않을 긴 질문도 빈 `ask` 칸부터 써서 첫 글이 늦음 |
| 숫자 | 애매한 질문 맞음 66.7 → 78.8%(72문항) | 애매한 한 낱말 되묻기 3/32 → 30/32(80문항) | 되묻기 기대대로 146 → 148/156(그대로) |

- 「낱말 수」 기준도 셋이라 섞이기 쉽습니다: **한 낱말**(v1.17.0, 「엄마」·「AI」는 「책 찾기 아님」이어도 2차로), **2낱말 이하**(v1.18.0, 「후보 분야」 줄, `SHORT_QUESTION_WORDS`), **4낱말 이하**(v1.19.0, 되묻기 형식, `ASK_QUESTION_WORDS`). v1.21.0부터 첫 질문이 한 낱말이면 되묻지 않고 갈래를 섞어 바로 답합니다.
- 「책 찾기 아님」의 답은 v1.17.0~v1.20.6에서는 고정 문구와 예시 3개였고, v1.21.0부터는 Haiku가 답과 선택지를 만듭니다(실패하면 고정 문구). 2차의 되묻기와 다릅니다.

**1차를 ML로 바꾼 세 단계**

| | v1.16.0 1차 ML | v1.16.1 관계 분류기 | v1.16.3 합치기 |
|---|---|---|---|
| 무엇 | 첫 질문(과 이어 묻는 질문)의 길·칸을 질문 벡터 위 MLP가 정함. 이어 묻는 질문은 「새 주제 규칙」 | 이어 묻는 질문이 앞 질문과 어떤 관계인지 **두 번째 MLP**(7가지)가 정함 | 「둘 다」·「섞은」 같은 말이면 **앞 질문 여러 개**를 이어 붙임. 모델이 아니라 신호 말 규칙(`EarlierTopics`) |
| 파일·설정 | `first-call-model.bin`, `book-profiles.tsv`, `FIRST_CALL=ml` | `follow-up-model.bin`, `FOLLOW_UP=relation` | 코드만 |
| 숫자 | 질문 57개 품질 그대로, 1차 Haiku 호출 0 | 대화 80개 continue 67 → 76% | 3턴 합치기 카드 0장 12 → 1 / 25 |

**책 수**: 1,911권(v1.10.0, 추천목록 책만) → 30,939권(v1.12.0, + 보유 도서관 많은 3만 권) → 27,227권(v1.15.0, 소개 없는 3,712권 뺌) → 76,759권(2026-10-26 21:59, 10만 권 판, 코드 배포 없음). 30k와 100k는 둘 다 「보유 도서관 많은 순」 같은 식이고 `book-texts-top-books` 값(30000 / 100000)만 다릅니다. 100k 넣기는 CHANGELOG에서는 v1.17.0 줄에 적혀 있지만 실제로는 그 2시간 전, v1.16.3 코드 위에서 들어갔습니다.

**첫 글 시간을 줄인 두 번**

| | v1.17.0 생각 끄기 | v1.19.0 겹치기 |
|---|---|---|
| 무엇을 줄였나 | Haiku가 첫 글자를 내기까지(생각 단계) | Haiku를 부르기 **전** 준비(낱말 검색, 표지·요약 읽기)와 Haiku 첫 토큰 **뒤** 빈 `ask` 칸 |
| 대가 | 질문당 맞는 카드(2점 이상) 6.7 → 5.8장(57문항) | 4낱말 이하 질문은 그대로 둠 |
| 숫자 | 4.0 → 2.3초(72문항 두 번, 로컬) | 5낱말 이상 첫 질문 1.68 → 1.43초(80문항, 로컬), 운영 2.63 → 2.06~2.25초 |

- 두 숫자는 질문 묶음이 달라 이어 읽을 수 없습니다(v1.17.0 뒤 2.3초 → v1.19.0 앞 1.68초가 아님). v1.16.0의 「8.6 → 8.1초」는 **답이 끝날 때까지** 시간이라 첫 글 시간이 아닙니다.

**「이웃을 후보로」 네 가지**: v1.11.0은 「이 중에」(앞 책 가리킴) → 앞 턴 책의 이웃 최대 12권. v1.15.0은 「○○ 같은 책」(질문 속 책 제목) → 그 책의 이웃 20권 먼저. v1.16.2는 앞 책 가리킴 → 바로 앞 턴 말고 그 전 턴들의 책도. v1.16.3은 합치기·조건 더하기(continue) → 앞에서 보인 책을 다시 후보에(전에는 뺐음).

**카드 수를 바꾼 고침**: v1.10.2 fit 2 미만 숨김(카드 줄 수 있음) · v1.16.3 「맞는 책이 적으면 적게, 반대인 책으로 채우지 않음」(줄 수 있음) · v1.17.0 생각 끄기(줄어듦, 의도 아님) · v1.18.0 「맞는 책이 여럿이면 8권까지」(늘림). 운영 기록의 질문당 카드는 6.1(v1.15) → 5.1(v1.16.0~2) → 4.8장(v1.16.3)이었는데, 질문이 매번 달라 참고만 합니다([모음 8절](4-results.md#8-책을-10만-권으로)).

**AI 호출 수**: v1.10.0~v1.15.x는 검색 한 번에 Haiku 2번(1차 + 2차). v1.16.0부터 보통 질문은 1번(2차만), 책첵 질문은 사이트 답 1번, 「책 찾기 아님」은 0번(v1.17.0부터 낱말 하나짜리는 책 찾기로 바꿔 2차 1번). 질문 벡터가 늦거나 실패하면 그 검색만 1차 Haiku로 돌아가 2번.
