# 사이클 09: 수집 세션에 전달 (도서관 이름은 기관 이름만)

- 작성: chaekcheck-dev, 2026-10-12
- 근거: plan ADR-0071, ADR-0076, 사이클 09 인계서 "수집 세션 할 일", spec R1-7 ("이렇게 가자", 사용자, 2026-10-11)
- dev 기록: `docs/plan-feedback.md` `# 사이클 09`, `docs/library-maintenance.md` 4-13

## 1. 무엇이 바뀌었나 (서비스 쪽, 이미 끝남)

- 서비스 도서관 이름에서 이름 끝의 업체·대출 방식 괄호를 뗐습니다(`(교보)`, `(YES24)`, `(북큐브)`, `(알라딘)`, `(구독)`, `(구독형)`, `(소장)`, `(대여)`, `(교보, 호스트)` 등 277곳). 공식 이름이 바뀐 곳(학교 통합·개명 등)도 함께 고쳤습니다. 모두 289곳입니다.
- 기관 이름 속 괄호((주), (부산), (경기), 캠퍼스·부서 이름 등)는 그대로 둡니다.
- 같은 기관의 사이트 여러 개는 이제 이름이 아니라 **업체(`vendor`) · 대출 방식(`lending_model`) · 순번(`order_no`)** 으로 구분합니다. 서비스 DB는 (이름, 업체, 대출 방식, 순번)이 같으면 거절합니다.
- 서비스의 "넣기" 스크립트(dev `scripts/library/build_candidate_seed.py`)가 바뀌었습니다.
  - 새 후보 도서관은 **수집 DB 이름을 그대로** 받습니다. 예전처럼 이름이 겹친다고 괄호 라벨을 붙이지 않습니다.
  - 업체는 "수집이 따로 적은 값이 있으면 그 값, 없으면 화면 종류 대응표"입니다. 대응표: `KYOBO_V1`·`KYOBO_SUBSCRIPTION_V1` → `KYOBO`, `YES24_V1~V3` → `YES24`, `BOOKCUBE_FX` → `BOOKCUBE`, `ALADIN_V1` → `ALADIN`, `ELIB_PORTAL_V1` → `PORTAL`, `GANGNAM_V1` → `IN_HOUSE`.
  - 대출 방식: 교보 구독형은 교보 probe 값(없으면 구독), 북큐브는 전체 권수(`totalVolume`)가 0이고 책(`totalItem`)이 있으면 구독, 나머지는 소장, 통합 포털은 비움.
  - (이름, 업체, 대출 방식)이 같은 곳이 생기면 순번 2가 붙고 스크립트가 멈춥니다(종료 코드 3). 사람이 사이트 이름을 확인해 고칩니다.

**수집기(`crawl_catalog.py`)와 수집 DB는 dev가 고치지 않았습니다.** 수집 쪽에서 할 일은 아래 2~4절입니다.

## 2. 부탁: 수집 DB 도서관 이름 바꾸기 (필수)

- 대상: 수집 DB `chaekcheck-data\ebook-catalog.sqlite`의 `library.name`, 맨 아래 표 289곳
- 왜: 새 후보는 수집 DB 이름을 그대로 받으므로, 수집 DB에 괄호가 남아 있으면 다음 넣기 때 다시 붙습니다(예: 수집 100062 "부산광역시 전자도서관(구독)").
- 짝 찾기: **수집 번호(`library.id`)로** 찾습니다. 이름으로 찾지 않습니다. 서비스 번호 ↔ 수집 번호는 dev `backend/src/main/resources/db/changelog/collection/002-collection-link.csv`와 같습니다. 등록 도서관(수집 번호 < 100001)은 두 번호가 같습니다.
  - 표의 "서비스의 옛 이름"은 서비스 seed 이름이라, 수집 DB의 지금 이름과 다를 수 있습니다(서비스 넣기가 라벨을 붙였던 곳). 참고용입니다.
- 지킬 것 (사이클 08과 같은 원칙)
  - 수집기가 도는 동안 쓰기 충돌이 없게 합니다(방법·때는 수집 세션이 정함 [확인 필요]).
  - 사본(`snapshots\…`)은 건드리지 않습니다.
  - 교보 구독형 서버(103.182.126.192, `*.dkyobobook.co.kr` 대부분)에는 요청하지 않습니다(2026-10-07부터 막힘). 이름 바꾸기는 사이트 요청이 필요 없습니다.
- 같은 목록 파일(TSV): dev `data\cycle09\collection-rename-list.tsv` (칸: 서비스 번호, 수집 번호, 최종 이름; git 밖)

## 3. 정할 것: 수집이 업체를 따로 적는 자리 [확인 필요]

- 지금 수집 DB에는 업체를 적는 칸이 없습니다(`library` 칸: `id, name, platform_type, base_url, host, seed_holdings_count, last_full_success_at, last_full_run_id, source, crawl_skip`, 2026-10-05 사본 기준).
- dev 스크립트에는 자리만 있습니다: `build_candidate_seed.py`의 `COLLECTION_VENDORS = {}`(수집 번호 → 업체, `TODO(확인 필요)`). 지금은 모든 도서관이 대응표 값입니다.
- 화면 종류와 업체가 다른 곳(예: 같은 화면을 다른 업체가 운영)이 생기면 수집 쪽에서 적을 자리와 꼴을 정해 알려 주세요. 값은 `KYOBO`, `YES24`, `BOOKCUBE`, `ALADIN`, `PORTAL`, `IN_HOUSE` 여섯 가지만 됩니다(서비스 DB CHECK).

## 4. 다음 수집 때 알아 둘 것

- **새로 찾은 도서관 이름은 기관 정식 이름만** 적어 주세요. 업체·대출 방식 괄호를 붙이지 않습니다. 같은 기관의 두 사이트(예: 교보와 YES24)는 같은 이름이어도 됩니다.
- **북큐브 대출 방식**: 서비스는 북큐브 사이트별 `totalItem`·`totalVolume`(전체 권수)로 구독인지 정합니다. 이번에는 plan이 2026-10-11에 받은 값(dev `scripts/library/bookcube-volume-2026-10-11.tsv`, 칸 `id, name, base_url, totalItem, totalVolume, error`, `id`는 수집 번호)을 썼습니다. 지금 구독은 서비스 339·380·386·705(수집 100062·100108·100114·100442)입니다.
  - 책 0종이거나 응답이 없던 5곳(수집 100045, 100048, 100256, 100391, 100440)은 지금 소장으로 둡니다. 다음 수집 때 다시 받아 주시면 좋습니다(plan "이번에 하지 않는 것").
  - 새 북큐브 후보를 넣을 때도 같은 꼴의 파일이 필요합니다.
- 교보 구독형 대출 방식은 지금처럼 교보 기관 probe(`other-platforms\kyobo-institutions-probe-*.tsv`의 `model`)에서 옵니다.
